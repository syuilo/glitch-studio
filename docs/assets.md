# Assets

## メディア入力の扱い

Glitch Studioのメディアの扱いにあたっては、以下の概念があります。

- **Asset** ... プロジェクトに読み込んだ画像ファイル、動画ファイル、音声ファイルなどの素材
- **Player** ... 動画・音声Assetや、Webカメラ、ライブストリーム(URL)などのメディアソースを参照し、UI上で再生コントロールを提供する
- **Node** ... Player(のID)を参照し、映像や音声を使って描画する。画像は、静的であってコントロールが不要なので直接Asset(のID)を参照する

同じAssetでもそれに対応するPlayerは複数存在し得ます(同じAssetをそれぞれ異なった再生位置で複数再生させるなど)。

同じPlayerでもそれに対応するNodeは複数存在し得ます(同じPlayerでもフレーム描画エフェクトと音声波形描画エフェクトなど、複数のNodeから参照するなど)。

なお、Playerはタイムラインレンダリングでは非対応です。

## 埋め込みと外部参照

`ProjectAsset.isExternalReference`は素材の保存方法を表します。初期値は埋め込みで、Electronの設定から新規取り込みのデフォルトを外部参照へ変更できます。Replaceは既存のモードを維持します。実ファイルのパスが得られない素材は常に埋め込みです。

Electronの設定「30MB以上のファイルを常に外部参照として取り込む」を有効にすると、デフォルトが埋め込みでも30,000,000バイト以上の新規ファイルを外部参照にします。初期値はオフです。複数選択時はファイルごとに、原本を読み込む前にサイズを判定します。Replaceと明示的なモード変換は対象外で、Web版とパスのない素材は埋め込みのままです。

埋め込みは取り込み時の原本をBlobとしてコピーし、`.gsproj`にも原本を保存します。外部参照は`sourceFilePath`のファイルを直接読み、`.gsproj`には原本を含めません。Electronの実行中は絶対パスへ解決し、保存時はプロジェクトのディレクトリ配下だけ相対パスにします。親・兄弟ディレクトリや別ドライブは絶対パスです。別名保存では新しい保存先を基準に再計算し、参照先自体は変えません。埋め込みモードのパス記録も同じ規則で保存します。

外部参照のURLはElectronが実行時に発行し、動画・音声はMediabunnyの範囲読み取りと上限付きキャッシュを利用します。原本全体のBlobやArrayBufferを作りません。画像はアセット同期時に、フォント・LUTは使用時に必要なデータを読み込みます。subsystemにはBlobまたはURLの汎用的な読み取り口だけを渡し、保存方法と実パスの解決はGlitch Studio層が担当します。

GsAssetのメニューから、リロード、再リンク、外部参照から埋め込みへの変換ができます。埋め込みから外部参照への変換ではファイルを選択し、そのファイルの内容を使います。選択開始位置には記録した`sourceFilePath`のディレクトリを使います。「埋め込みファイルを書き出す」は独立した操作で、モードやパスを変更しません。

リロードはUndo対象外です。再リンクとモード変換はUndo/Redoでき、アセットIDと表示名を維持します。外部原本の過去の内容は復元せず、書き出したファイルをUndoで削除しません。リロードで寸法・サムネイルなどの保存対象情報が変わる場合は変更済みになります。クリップの配置やトリム範囲を自動変更しません。

`ProjectContext`の`ExternalAssetMetadataStore`が、アセットIDと参照先パスごとの最新の寸法・種類・サムネイルを編集履歴とは別に保持します。再リンクや取り込みのUndo/Redoでアセットが復元されても、レンダラーへの同期前に、その参照先の最新の取り込み・リロード結果を適用します。埋め込みの原本とメタデータは履歴から復元します。この管理情報はプロジェクトの読み込み時に初期化し、外部原本のバイト列は保持しません。URLと参照切れの状態は従来どおり現在の参照先から解決します。

素材・Playerの定義は、レンダラーの初期化時に固定します。追加・削除・原本や寸法・Playerの参照先が変わると両プレビューを停止・破棄し、最新状態から再生成します。その際はUI側のPlayerメディア要素も全再作成するため、無関係な動画・音声の再生位置や再生状態もリセットし、Webcamを再取得します。エラーからのエンジン再生成も同じ扱いです。素材名・Player名・サムネイルだけの変更では再生成しません。

参照切れはプロジェクト読み込み、リロード、アプリへのフォーカス復帰、読み取り失敗時に確認します。常時監視やフォーカス復帰時の内容の自動リロードは行いません。外部原本は直接読むため、リロード前の内容を固定する保証はありません。GsAssetに警告と参照先を表示し、手動で再リンクできます。参照切れでもプロジェクトの読み込み・保存は可能で、未使用の素材はほかの描画を妨げません。実際に使用する描画はエラーになり、プレビューを停止し、動画書き出しも失敗させます。

Web版は外部参照の作成・解決に対応せず、参照情報を保持して利用不可を表示します。Webでの保存はパス表記を変更せず、別フォルダーへ移した場合の相対パスの再計算は行いません。

`.gsvm`書き出しでは外部参照も原本を埋め込み、プロジェクト内のモードは変更しません。参照切れなら書き出しに失敗します。外部参照から埋め込みへの変換と`.gsvm`書き出しには、原本全体を読み込むメモリ制約が残ります。プロジェクトのバックアップは外部原本を含まず、参照情報だけを保存します。

## ファイルの取り込み

アプリケーション全体で、種類を制限せず複数ファイルのドロップを受け付けます。AssetsパネルのAdd assetも同じ取り込み処理を使います。ファイルを選択順に直列で読み込み、画像・動画・音声以外はデコードせず原本を保存します。MIMEが空のファイルは`application/octet-stream`として保存し、フォントのMIMEは拡張子も用いて正規化します。読み込み失敗は最後にまとめて通知します。成功したAssetと音声・動画用のPlayerは`importAssets` Commandで一括追加し、一回のUndo/Redoで戻せます。

取り込み開始からプロジェクト反映の完了まで`ui.progress()`で操作を止めます。複数ファイルではメインを完了件数／総件数、subProgressを現在のファイルのサムネイル生成進捗として扱い、読み込み時間を計算できない段階はnullで待機状態を表示します。単一ファイルはメインのみを使います。`setText()`でファイル名・順番・処理段階を更新します。途中で別プロジェクトへ切り替わることは想定しません。

`utility/file-drop.ts`は`App.vue`のルート要素で、通常のバブリングによって届いた外部ファイルを受け付けます。子要素でstopPropagationしたイベントと、ルート外のpopupは全体受付へ届きません。WorkspacePanelなどのアプリ内ドラッグは既存の処理へ通します。dropイベント中にFile一覧を保存し、非同期処理へ渡します。全体ドロップはアセット取り込み専用で、プロジェクトファイルを開きません。取り込み後に`revealPanel({ contentType: 'assets', sourcePanelId: null })`で既存のAssetsパネルを開き、パネルを削除したレイアウトには追加しません。書き出しダイアログではドロップを受け付けません。GsDraggableは同じグループの内部ドラッグだけ伝播を止め、対象外のファイルは全体受付へ渡します。

`GsDashboardDialog.vue`は`installFileDropHandlers`を背景を含むモーダル全体へ登録し、受付・操作ロック・二重ドロップ防止を共通化します。ファイルの扱いはAppの全体受付とは独立して所有します。単独の`.gsproj`では、コールバックへ同期的に渡されたdropイベントから保存先ハンドルの取得をawait前に開始してプロジェクトを開きます。単一の画像・動画・音声はOpen Mediaと同じ`newProjectFromImageOrVideo()`へ渡し、素材に合わせたノード・レイヤー・解像度で新規プロジェクトを作ります。複数アセットやメディア以外のファイルではプロジェクトがない場合だけ新規作成して全ファイルを取り込みます。成功後にDashboardを閉じ、破棄時に受付を解除します。全体受付との二重処理を避けるための専用属性は使いません。

`GsDetachableView.vue`もPiP・別ウィンドウへ移したビュー要素に同じバブリングのアセット受付処理を登録し、メイン画面の操作ロックを参照します。ビューの復帰・ウィンドウ終了時には登録を解除します。

`GsAssetSelectDialog.vue`は背景を含むモーダル全体で任意の種類の複数ファイルを受け付け、ホバー中はダイアログに「Drop here」を表示します。`GsModal.getRootElement()`が返す背景とコンテンツを含む要素へ受付を登録します。Add Assetと同じ取り込み処理・進捗表示を使い、成功時はAssetsパネルを開きます。取り込みだけで選択を確定せず、一覧のMIME絞り込みと既存の選択操作を維持します。操作ロック中・取り込み中は追加のドロップを受け付けず、ダイアログ破棄時に受付を解除します。

`GsTimeline.vue`は全体受付とは独立して、外部ファイルと`GsAsset.vue`のドラッグを受け付けます。コンポーネント内のcaptureで対象イベントの伝播を止め、レイヤー行の並び替えと区別します。ホバー中は全体に「Drop here」を表示し、フォントも表示対象に含めます。画像・動画・音声はScene直下の最上段へ入力順に追加し、ドロップ時の再生ヘッド位置から画像は5秒、動画・音声は素材全長を配置します。外部ファイルは先に取り込み、`importAssets` CommandでAsset・Player・レイヤーを一括反映します。配置できない素材もAssetsに保存し、Assetsパネルを開きます。既存Assetのドロップは取り込みを行わず、配置対象外なら無視します。読み込み・配置まで進捗ダイアログを維持し、映像だけ利用できる動画は音声を無効にして警告します。

App.vueの全体受付でも、ファイルのホバー中は「Drop here」を表示します。専用受付で伝播が止められた場合や、アプリ外へ離れた場合は全体表示を消します。windowのcaptureでは表示状態だけをリセットし、ファイルの受付自体はルートの通常バブリングで行います。

## Visual Module Editorへのドロップ

`GsVisualModuleEditor.vue`はTimelineと共通の`useAssetDrop`でファイル・Assetのホバー表示と受付を行います。編集先と処理は親が`VisualModuleAssetDropActions`として渡し、登録済み・インラインの違いを共通Editorへ持ち込みません。画像はImage、動画はVideo、音声はAudio Waveformのノードを通常ノード一覧の末尾（出力ノードの直前）へ追加し、既存の配線と出力接続は保持します。動画・音声はそのAssetのPlayerを参照し、Playerがなければ作成します。

ファイルの読み込み・サムネイル生成からノード反映まで同じprogressダイアログを維持します。`importAssets`の配置準備コールバックへ読み込んだAsset・Player・ダイアログを渡し、`AssetImportPlacement`でTimelineまたはVisual Moduleへの配置を指定します。Asset・Player・ノードを一つのCommandで反映し、参照の検証が失敗した場合は部分追加しません。既存Assetは進捗ダイアログを表示せず、`addVisualModuleAssetNodes`で不足するPlayerとノードだけを追加します。ノードに対応しないファイルはAssetsへ取り込んでパネルを開き、同じ種類の既存Assetは無視します。

## 静的設定からのAsset参照

画像・動画・フォント・LUTを直接参照する静的設定は、`{ kind: 'assetReference', assetType: 'image' | 'video' | 'font' | 'lut' }`で表します。保存値はAsset IDまたはnullです。`assetType`は型の一部で、選択候補の絞り込み・描画前の検証・実行時のリソース解決に共通のMIME制約を使います。参照の収集・ID再割り当て・削除時の参照解除は種類によらず扱います。

画像の`assetReference`は実行時にGPUTextureへ解決します。`imageAssetTextureReference`は廃止しました。動画の`assetReference`は素材を直接参照し、Playerの再生状態を参照しません。

素材・PlayerのIDは静的設定に直接保存し、通常パラメータ・Custom Parameterでは公開しません。Textレイヤーのフォントは`textStaticSettings.font`、VOICEVOX字幕は`subtitleStaticSettings.font`に保存します。

## LUT Asset

`.cube`は取り込み時に`application/x-cube-lut`へ正規化し、原本のBlobを保存します。表示名の拡張子を再判定しないため、改名後も種類は維持されます。Playerは作りません。内容の解析・検証はエフェクトが使用する際に行い、取り込み時にはデコードしません。

`{ kind: 'assetReference', assetType: 'lut' }`はAsset IDまたはnullを保存し、LUTだけを選択候補に表示します。Asset差し替え、Visual Module内の参照解除とUndo/Redo、`.gsproj`の原本保存、`.gsvm`の参照収集とID再割り当てに対応します。未選択は入力を通し、不正なファイルは描画エラーになります。その他のAsset参照と同様に、タイムラインの静的設定などに残った参照切れは描画前の検証で通知します。

LUTの解析・GPU処理はEffect subsystemの`fx/applyLut`が所有し、UIやプロジェクトに依存しません。詳しくは[Apply LUT](../packages/subsystems/effect/shared/src/fx/applyLut/README.md)を参照してください。

## 動画サムネイル

動画の取り込み・差し替え時には、主映像トラックの0%から100%まで10%間隔でサムネイルを生成します。100%は最後のフレームです。長辺を320px以下に縮小し、小さな動画は拡大しません。同じtimestampに対応する地点は重複保存しません。

`ProjectAsset.thumbnailSequence`は寸法と、実際のフレーム時刻・画像Blobの列を所有します。レンダリング用の`Asset`には追加せず、Workerへの素材同期・書き出しでは表示用情報を除きます。`.gsproj`では画像バイト列と実際のMIMEを保存します。`.gsvm`には含めません。

`api.ts`が取り込み完了前に生成を待ち、`utility/open-media-file.ts`が`ui.progress()`で取り込み全体とファイル単位の進捗を表示します。生成失敗は素材本体の取り込みを妨げず、サムネイルなしとして扱います。`importAssets`・`addAsset`・`replaceAsset` Commandは原本とサムネイル列を一緒に扱います。

`GsAsset.vue`が使う`GsAssetThumbnail.vue`は、画面内の画像を表示し、動画は500ms間隔で次の画像へ切り替えます。画面外・折りたたみ・非表示タブでは停止し、差し替え・非表示・アンマウントでタイマーとObject URLを解放します。画像の先読みは次の1枚だけです。
