Glitch Studioとして、各subsystemのレンダラーを利用する統括層

`CanvasRenderer`は完成画像と映像解析の描画を担当する。`previewDisplayMode`が`gpu`の場合はGPUCanvasContextへ直接出力し、`cpu`の場合は`CpuPreviewCanvasContext`の通常GPUTextureへ出力して読み戻す。どちらも同じ描画・集計パスを使う。CPU方式では行padding・BGRA/RGBA・乗算済みalphaをImageData用へ変換し、`cpuPreviewFrame`イベントでピクセルの所有権をUIへ転送する。UIはCanvas 2Dへ表示してから`recycleCpuPreviewPixels`で領域を返却し、GPU読み戻し・CPUピクセル領域を再利用する。古いサイズ・世代・完了順の画像は送信しない。

CPU表示の画素変換では、little endianかつ4byte境界のメモリ配置なら、不透明画素を32bit単位でコピーし、BGRAの赤青交換もビット演算で行う。半透明画素の未乗算RGBへの補正は従来と同じ丸め・clampを保つ。32bitで扱えない配置やエンディアンではbyte単位の変換へ戻る。転送量・表示解像度は変えない。

CPU表示の上限は`CpuPreviewFrameQueue`で一元管理する。ノード評価・描画の前に最大2フレーム分を予約し、読み戻し完了後も主映像・解析用の全出力がUIから返却されるまで保持する。Timelineは満杯なら予約を待ち、シーク先やBAKEの最終画像を省略しない。Visual Module Live Previewは満杯なら評価・GPU描画・映像解析の前に間引き、経過時間を次のTIME_DELTAへ加算する。予約後に出力寸法が変わっても、そのフレームの予約は維持する。編集・停止・破棄では未完了の予約を解放し、旧画像の送信や意図した破棄によるエラー通知を防ぐ。

読み戻しコピーは最終描画と同じencoderへ記録し、一度のsubmit後にmapAsyncを開始する。読み戻し専用のencoder・submitは作らない。Timelineのキャッシュ確保失敗を通常表示から隔離する別submitは維持する。GPU処理とピクセル送信後に完了を通知し、同じWorker通信路で画像が先に届くためUIでの手動シーク完了は描画後になる。encoder記録・finish・submitの失敗でも予約と読み戻しbufferを回収する。書き出しは従来のGPU経路を使う。

レイヤー階層の同期はScene設定の世代を進めない。`ProjectStateVersions`は階層内のIDの追加・削除・種類変更と、個別の設定変更から再生成対象を決める。同じ親に残る配置の並べ替えでは履歴を保持し、親変更では各グループのTimelineRendererが移動元の配置を解放して移動先で生成する。グループ自身の設定は毎回読み直すため子の履歴を破棄せず、グループ削除後の復元は新しい世代として扱う。

Timelineの変形プレビューは、UIが`transformObserver`で購読した同じScene内の一レイヤーについて、通常の描画で得た合成前の寸法・変形値と祖先グループの変形値を通知する。GPUからの画像読み戻し・ポーリング・ハンドル用の追加描画は行わない。変化のない同時刻の再描画は通知せず、モーションブラーの全サンプルを一つの通知へまとめ、変形値は基準時刻に揃える。購読IDと既存更新RPCへ同梱する`previewRevision`により、選択や編集より古い応答をUI側で破棄する。書き出しでは購読しない。

Glitch Studioのドメイン知識を持っていてもよい

`TimelineAudioInputs`は波形・スペクトラム描画用の音声入力を統括する。Assetからファイルを解決し、Audio subsystemのデコーダー・PCMキャッシュとTimeline Audio Rendererを接続する。再生Workerとは独立した読み出しを使い、同じデコーダーへの並行seekは直列化する。音声計画は取得元Scene・下層/指定レイヤーの方式・レイヤーIDごとに保持する。Scene定義の更新時に音声計画を無効化する。Asset一覧は生成時に固定し、変更時には所有するManagerごと再生成してデコーダー・PCMキャッシュを解放する。指定先が同じSceneにない、または音声出力を持たない場合は入力なしを返し、別Sceneへ探しに行かない。古い入力の完了は中断された描画へ採用せず、実行中の読み出しが終わってからデコーダーを解放する。

描画要求のキャンセルは読み出しキューとAudio subsystemへ伝える。実行前に中断された読み出しをスキップし、実行中の処理もデコードブロック・窓・クリップの境界で終了する。中断した要求のために後続の素材を読み続けない。

`PlayerAudioInputs`はVisual Module Live PreviewのPlayer指定を解決し、取得元の履歴状態ごとに固定した`AudioInput`を共有する。同じ入力を読む複数ノードや履歴の変わらない描画では入力を共有する。追記・リセット・取得元の差し替えは新しいスナップショットにするが、PCMは不変ブロックのまま共有し、区間と参照だけを固定する。窓取得も必要なブロックを参照し、履歴全体・要求区間のPCMを再複製しない。過去の入力が参照するPCMは変更しない。Visual Moduleには`resolveAudioSource`を注入し、Player指定の解釈とスナップショットの所有をGlitch Studio側に保つ。

タイムラインの`timelineFps`と`timelineMotionBlur`は`TimelineRendererManager`のstatic optionsとして初期化時に確定する。変更時はUI側のControllerがWorkerごと再生成し、キャッシュ・エフェクトの履歴・蓄積用GPUリソースを引き継がない。fpsとブラー設定の同時適用は1回にまとめ、再生成中の後続変更も最新値まで反映する。

プレビュー用のサンプル数はUIがプロジェクトと別に所有する。UIはプレビュー用Managerを作る際に`timelineMotionBlur.samples`をUIの選択値で上書きし、書き出し用Managerには保存されたプロジェクトのサンプル数を渡す。レンダラーはプレビュー専用のサンプル数フィールドやプロジェクトの既定値を持たない。

プレビューfps倍率は描画要求の頻度とフレーム境界を決める。UIは実効fpsをdynamic optionsの`previewFps`として送り、変更時は描画インスタンスとフレームキャッシュを破棄する。Worker自体の再生成は不要。動画書き出しでは呼び出し側が指定したfpsを露光時間の基準に使い、静止画とプレビューではstatic optionsの`timelineFps`を使う。ブラー無効・シャッター角0・サンプル数0/1の場合は`TimelineRenderer.renderAt()`で単発描画し、複数サンプル用の管理を経由しない。

ブラウザー版・Electron版のタイムラインプレビューは、Scene枠へ確定したモーションブラー適用後・表示処理前の最終画像を`TimelinePreviewFrameCache`へ複製する。キャッシュ画像は独立したGPUTextureで、元の形式・float精度・premultiplied alphaを保持する。次の描画で更新される作業用画像の参照だけを保存しない。GPU完了後に開始時の内容世代が有効な画像だけを登録する。ヒット時もCanvasRendererを通し、表示設定・波形・ヒストグラム・要求されたシーク完了通知を維持する。

上限は編集ウィンドウごとの環境設定（既定2GiB、0で無効）とし、幅×高さ×形式のバイト数の合計で推定する。OS全体のVRAM使用量やドライバーの実割当量は計測しない。保存前・容量縮小時にLRUで削除し、一枚で上限を超える画像は保存しない。編集・素材・生成音声・Scene・解像度・プレビューfps・精度・ブラー設定の変更で全消去する。選択や表示上の警告の変更では保持する。履歴依存エフェクトも一律にキャッシュし、ヒット時の履歴更新・復元は行わないため、ミスへの切替時や書き出しとの結果一致は保証しない。書き出しは上限0で動作する。

変形ハンドルはキャッシュ生成時に同じScene内のレイヤーの寸法・変形情報を保存し、後の選択変更でも画像の再評価なしで復元する。保存・削除で変化した連続フレーム区間と推定容量を約100msごとに`frameCache`で通知する。LRU順の更新だけでは通知せず、計測設定とは独立して動作する。

タイムラインのプレビューは、再生・シーク・一時停止とも`TimelinePreviewScheduler`へ渡す。CPU側の素材準備・評価・コマンド送信は直列に行い、送信済みでGPU完了待ちのフレーム数を静的オプション`previewFramesAhead + 1`件まで許可する。`previewFramesAhead`の省略時は1（合計2件）、0ではGPU完了まで直列に処理する。UIの環境設定は0〜3を受け付け、変更時はWorkerを再生成するため、旧フレームの処理とキャッシュは持ち越さない。小さなUIアニメーションがあるだけでGPU完了待ちが長くなる環境でも、先行を許可すると1件目の完了通知を待つ間に次の準備を進められる。待機要求は最新1件へ上書きする。進行中のフレームは通常のシークでは中断せず、音声時計・再生時刻はUI側で進め続ける。シーク先が表示されるまで描画済みの画像を保ち、進行中だった古い時刻の画像が一時的に表示されることは許容する。

プレビューの`timeDelta`（ms）は、今回のタイムライン時刻から直前にCPU側の評価・送信が成功した時刻を引いた値を使う。GPU完了後の後処理順や、省略された要求の時刻は基準にしない。同時刻の再描画は0、逆方向のシークは負の値をそのまま各エフェクトへ渡す。初回とスケジューラーの`clear()`後は0とし、初期化前の処理が遅れて完了しても基準時刻を引き継がない。モーションブラーではこの差をフレーム本来の経過時間として渡し、各サンプルの時間差は従来どおりサンプル間で求める。

両Managerの素材一覧とVisual Module Live PreviewのPlayer定義は、非同期factoryの`create(coreConfig, staticOptions, resources, signal?)`で受け取り、寿命中に変更しない。コンストラクターは非公開とし、factoryが`AssetTextures`の画像デコード・GPU転送を待ってから描画可能なManagerを返す。渡されたGPUDeviceはManagerが所有し、生成失敗・AbortSignalによる中断時もfactoryが回収する。中断時はデコード完了を待たずに生成待機を終了し、遅れて完了したデコードではGPUを使用せずBitmapだけを閉じる。CanvasからGPUを準備する`createManager()`と書き出しは、ともにこのfactoryを使う。`createManager()`は同期処理の`updateDynamicOptions()`で初期設定を適用してから返す。`assets`・`players`はdynamic optionsに含めず、更新時はUI側でManagerを破棄・再生成する。描画中の素材待機や更新要求間の世代管理は持たない。

GPUを所有するManagerが、最終表示とモーションブラーの全サンプルをsubmitした後に送信済みを通知し、`queue.onSubmittedWorkDone()`を待つ。画像キャッシュの登録・シーク完了通知・統計の集計は引き続き実際のGPU完了後に行う。GPU待機中の計測や変形情報は各フレームが保持し、後処理の完了順が入れ替わっても最新の変形情報を古い結果で上書きしない。途中の失敗や編集による中断でも送信済み処理を待ち、編集・Scene切り替え・失敗後の再試行は旧フレームのGPU処理を追い越さない。直接呼び出した`renderTimelineAt()`の戻り値も送信済み全フレームの完了を待つ。書き出し用の`renderTimelineFrame()`はこのスケジューラーを経由せず、呼び出し側が全フレームを順番に描画・エンコードする。

両Managerはstatic optionsの`enableStats`で計測の有無を決める。無効時は統計通知タイマーを作らず、Timelineの時計読み出し・動画計測コールバック、Live PreviewのFPS集計・TimingHelper・GPUメモリ追跡を停止する。TimingHelperは計測するデバイスのqueueだけをラップし、import時にGPUQueueのプロトタイプを変更しない。書き出しの`renderTimelineFrame()`は計測経路を使わず、書き出しWorkerも明示的に無効を指定する。

プレビューのヒストグラム・縦横の波形は、両Managerのstatic optionsの`enableWaveformAndHistogram`でまとめて制御する。`CanvasRenderer`は無効時に解析用インスタンスを生成せず、バッファ・pipelineの確保もcompute/render passも省く。通常のCanvas出力や計測の有効・無効とは独立し、エフェクトとして配置した波形・ヒストグラムには適用しない。書き出しWorkerでは常に無効を指定する。

有効時のタイムラインのプレビュー計測は`performance.now()`の実経過時間を使い、フレーム全体・動画取得待ち・動画取り込みのCPU側処理・GPU完了待ちを分ける。フレーム全体は処理開始からGPU完了（CPU表示方式では読み戻し・RGBA変換・UIへの送信）までで、Scheduler内の順番待ちとUIでのCanvas描画は含めない。動画取得はファイル読み取り・初期化・デコード・キャッシュ待ちを含む。取り込みは変換・転送API・submitのCPU側時間で、GPU完了待ちは最終submit後の残りのキュー待ちであり、どちらもGPUの総実行時間ではない。計測のためだけのGPU同期や画像読み戻しは追加しない。

動画レイヤーの計測を子Scene・複数レイヤー・モーションブラーの全サンプルについて一つの出力フレームへ合算する。取得・取り込みのキャッシュヒットは省略した処理を0として扱う。書き出し・失敗・編集で無効になったフレームは集計しない。`TimelinePreviewStatisticsCollector`は通知間の正常完了フレームから平均と項目ごとの最大値を作り、約100msごとに`telemetry`で通知する。Scene・編集世代の異なるフレームは混ぜず、UI側も古い世代を採用しない。新しい完了フレームがなければ通知せず、破棄時に通知タイマーを停止する。

注意する必要があるのは、すべてのサブシステムは公平だということです。

TimelineはVisual Moduleを使用し、Visual ModuleはEffectを使用するという依存の階層構造自体はあるが、それは「Glitch Studioにおいてはタイムラインがメイン機能であり、タイムラインがすべてをk管理する」などということは意味せず、Glitch Studio自体の設計とは全く関係がない。

プロジェクト共通のAutomation Graphは両Managerのプロジェクト状態として同期する。Timeline Managerは保存用Sceneと評価用Sceneを分け、Glitch Studio sharedで各レイヤーの定義へ共通定義を加えてからTimelineへ渡す。共通定義の変更時は既存のTimeline描画インスタンスを破棄し、停止中の同一時刻でも最新の曲線を評価する。カメラ・Transform・合成設定・音声入力にも同じ一覧を使う。Live Preview Managerは公開パラメータへの入力評価にだけ共通定義を渡し、Visual Module内部には渡さない。音声試聴と書き出しも評価用Sceneから音声計画を作り、所属Sceneの時計を維持する。
