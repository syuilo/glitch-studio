Glitch Studioとして、各subsystemのレンダラーを利用する統括層

両Managerの`previewGamutWarning`は`{ enabled, referenceGamut, bounds }`で、初期値は無効・sRGB・`unit`。Display P3・Rec.2020・Adobe RGB・ACEScg（AP1参照）も選べる。`bounds`は色域から独立し、`nonNegative`は負の成分のみ、`unit`は負値または1超の成分を警告する。ACEScgは白色点順応を含むAP1の参照であり、ACESの表示変換や保存値の有効性を調べるものではない。

両Managerの`previewWarningImageSource`は黒・白と色域外に共通の判定対象で、既定の`original`は表示補正前のレンダリング画像、`previewAdjusted`はalphaを保ったまま露出・現在有効な色域圧縮を適用した画像を使う。どちらもプレビュー背景を含めず、背景合成・sRGB確認のclamp・Canvas出力は判定後に行う。確認中は表示と同じく色域圧縮を停止する。判定・通常の表示変換・警告色の重ね描きを分離し、警告色を判定や色域圧縮へ戻さない。

`CanvasRenderer`は範囲外なら表示補正後に不透明な黄色の斜線を重ね、黒・白の警告を優先する。判定行列は`@gs/shared/rgb-gamut.ts`と共有し、HALFの量子化誤差を行列の絶対値で伝播させて境界上の誤警告を避ける。最小刻みの誤差も表示調整後では露出に追従させる。判定画像のalpha>0は未乗算RGB、alpha=0の発光は保存RGBを使う。元画像が完全透明の黒なら、背景だけを警告しないよう判定対象によらず除外する。表示専用で、解析・キャッシュ・書き出しの元画像は変えない。

`canvas-output.ts`はCanvasの画素形式・色空間を`CanvasOutputSettings`として定義する。`createCanvasOutputConfigurator()`と`CanvasRenderer`へ同じ設定を渡し、Canvas構成と最終描画pipelineの形式を一致させる。プレビューのfactoryはGPU表示なら`createGpuPreviewCanvasOutputSettings()`で拡張sRGBの`rgba16float`を選び、CPU表示と書き出しWorkerは8bit sRGBを使う。Managerへ直接渡す場合の既定値も8bit sRGBとする。露出・背景・色域圧縮は表示変換としてlinear上で処理し、`canvas-output.wgsl`が最後にsRGB encodeを行う。float出力ではRGBをclampせず、ブラウザーがモニターの色空間へ変換した後、`toneMapping: { mode: 'standard' }`によりSDR範囲へ表示する。8bit出力だけshaderでsRGBの範囲へ制限する。

両Managerのdynamic optionsの`previewGamutCompression`は、`{ mode, customAmount }`でプレビュー専用の色域圧縮を指定する。modeは`none`・`displayP3`・`rec2020`・`adobeRgb`・`acescg`・`custom`、customAmountは0〜1のクロマ削減率。既定は通常表示で、書き出し用Managerにも圧縮を引き継がない。`preview-image-adjustment.wgsl`で露出後・背景合成前のRGBAを調整し、表示・解析・警告が同じ処理を使う。alpha>0は未乗算色を圧縮して乗算済みへ戻し、alpha=0の発光は独立したRGBとして圧縮する。元画像・フレームキャッシュ・警告色自体は変更しない。

`previewSrgbProof`（既定false）はsRGB環境での見え方を確認する表示モード。露出・背景合成後にsRGB色域へclampし、元画像の見え方を確認するため色域圧縮は一時的に迂回する。圧縮設定自体は保持し、確認を解除すると復帰する。両Managerから`CanvasRenderer`のuniformへ渡し、未使用のプリセットLUTも生成しない。Canvas・pipeline・キャッシュを作り直さず、書き出しへは引き継がない。

`preview-gamut-compression.ts`は各色域のOKLCH境界を三次式の全交点から求め、色相720分割・明度256分割のLUTをWorker内で共有する。プリセットを初めて使う際だけGPUへ転送し、通常表示・カスタムだけなら表の生成・確保を省く。最終表示は補間したsRGB／基準色域のクロマ比を使い、境界付近の補間誤差を補正する。HDRの明るさの圧縮は行わず、基準白より外側は既存の露出で確認する。[色空間の規約](../../../docs/color-management.md)を参照。

`TimelineRendererManager.renderTimelineLinearFrame()`は専用の書き出しManagerで静止画を評価し、表示変換前の画像を所有する`LinearImageReadback`を返す。通常の書き出しと同じモーションブラー・IS_EXPORT・Scene出力を使う。呼び出し側は`readBlocks()`で上から順にHALF RGBAを取得し、最後に`dispose()`する。借用テクスチャにCOPY_SRCがなくても、表示処理を通さず読み戻し用ターゲットへ各画素を確定する。行paddingとGPUバッファの上限は読み戻し側で扱い、ファイル形式と圧縮はImage Codec subsystem・UIが担当する。

両Managerの`resetRenderHistory()`は、保持中の全エフェクトの描画履歴を初期化する。Timelineは準備中の描画・モーションブラーを中断し、スケジューラーと画像キャッシュの世代を進める。リセット前に送信したフレームのGPU完了を待ってから次の評価へ進み、古い完了によるキャッシュ登録・シーク完了通知を無効化する。キャッシュ消去は直ちにUIへ通知する。Visual Module Live Previewは描画ループの時計・Player・素材を保持し、次のフレームから新しい履歴で描画する。Playerの入力PCM履歴や解析モニターの履歴は消去しない。

`CanvasRenderer`は完成画像と映像解析の描画を担当する。`previewDisplayMode`が`gpu`の場合はGPUCanvasContextへ直接出力し、`cpu`の場合は`CpuPreviewCanvasContext`の通常GPUTextureへ出力して読み戻す。どちらも同じ描画・集計パスを使う。CPU方式では行padding・BGRA/RGBA・乗算済みalphaをImageData用へ変換し、`cpuPreviewFrame`イベントでピクセルの所有権をUIへ転送する。UIはCanvas 2Dへ表示してから`recycleCpuPreviewPixels`で領域を返却し、GPU読み戻し・CPUピクセル領域を再利用する。古いサイズ・世代・完了順の画像は送信しない。

主Canvasの構成は`createCanvasOutputConfigurator()`で共有する。黒・チェック背景を合成するプレビューと`opaqueOutput`は`alphaMode: 'opaque'`、背景のない透明書き出しは`premultiplied`を使う。出力設定は生成時に固定し、alphaModeが変わるときだけconfigureする。表示設定の適用だけでCanvasの画像やCPU読み戻しを繰り返し破棄しない。

CPU表示の画素変換では、little endianかつ4byte境界のメモリ配置なら、不透明画素を32bit単位でコピーし、BGRAの赤青交換もビット演算で行う。半透明画素の未乗算RGBへの補正は従来と同じ丸め・clampを保つ。32bitで扱えない配置やエンディアンではbyte単位の変換へ戻る。転送量・表示解像度は変えない。

CPU表示の上限は`CpuPreviewFrameQueue`で一元管理する。ノード評価・描画の前に最大2フレーム分を予約し、読み戻し完了後も主映像・解析用の全出力がUIから返却されるまで保持する。Timelineは満杯なら予約を待ち、シーク先やBAKEの最終画像を省略しない。Visual Module Live Previewは満杯なら評価・GPU描画・映像解析の前に間引き、経過時間を次のTIME_DELTAへ加算する。予約後に出力寸法が変わっても、そのフレームの予約は維持する。編集・停止・破棄では未完了の予約を解放し、旧画像の送信や意図した破棄によるエラー通知を防ぐ。

読み戻しコピーは最終描画と同じencoderへ記録し、表示用のsubmit後にmapAsyncを開始する。読み戻し専用のencoder・submitは作らない。Timelineのキャッシュ確保失敗を通常表示から隔離する別submitは維持する。GPU処理とピクセル送信後に完了を通知し、同じWorker通信路で画像が先に届くためUIでの手動シーク完了は描画後になる。encoder記録・finish・submitの失敗でも予約と読み戻しbufferを回収する。書き出しは従来のGPU経路を使う。

レイヤー階層の同期はScene設定の世代を進めない。`ProjectStateVersions`は階層内のIDの追加・削除・種類変更と、個別の設定変更から再生成対象を決める。同じ親に残る配置の並べ替えでは履歴を保持し、親変更では各グループのTimelineRendererが移動元の配置を解放して移動先で生成する。グループ自身の設定は毎回読み直すため子の履歴を破棄せず、グループ削除後の復元は新しい世代として扱う。

Timelineの変形プレビューは、UIが`transformObserver`で購読した同じScene内の一レイヤーについて、通常の描画で得た合成前の寸法・変形値と祖先グループの変形値を通知する。GPUからの画像読み戻し・ポーリング・ハンドル用の追加描画は行わない。変化のない同時刻の再描画は通知せず、モーションブラーの全サンプルを一つの通知へまとめ、変形値は基準時刻に揃える。購読IDと既存更新RPCへ同梱する`previewRevision`により、選択や編集より古い応答をUI側で破棄する。書き出しでは購読しない。

Glitch Studioのドメイン知識を持っていてもよい

静止画の書き出しは表示用Canvasから独立した読み戻し画像を使う。`renderTimelineLinearFrame()`は乗算済みHALFのlinear sRGB、`renderTimelineSrgbFrame()`は未乗算の8bit sRGBを返す。sRGBはシェーダー内でbyteへ丸めて整数テクスチャへ書き、UNORMの境界丸めやCanvasでの再量子化を避ける。両方の行padding・GPUバッファ上限・ブロックの所有権・中断は`image-readback-blocks.ts`で扱う。呼び出し側はブロックをコーデックへ渡し終えてから画像をdisposeする。WebPの圧縮中はGPUを使わないため、その時点で専用ManagerとGPUDeviceも解放する。

`TimelineAudioInputs`は波形・スペクトラム描画用の音声入力を統括する。Assetからファイルを解決し、Audio subsystemのデコーダー・PCMキャッシュとTimeline Audio Rendererを接続する。再生Workerとは独立した読み出しを使い、同じデコーダーへの並行seekは直列化する。音声計画は取得元Scene・下層/指定レイヤーの方式・レイヤーIDごとに保持する。Scene定義の更新時に音声計画を無効化する。Asset一覧は生成時に固定し、変更時には所有するManagerごと再生成してデコーダー・PCMキャッシュを解放する。指定先が同じSceneにない、または音声出力を持たない場合は入力なしを返し、別Sceneへ探しに行かない。古い入力の完了は中断された描画へ採用せず、実行中の読み出しが終わってからデコーダーを解放する。

描画要求のキャンセルは読み出しキューとAudio subsystemへ伝える。実行前に中断された読み出しをスキップし、実行中の処理もデコードブロック・窓・クリップの境界で終了する。中断した要求のために後続の素材を読み続けない。

`PlayerAudioInputs`はVisual Module Live PreviewのPlayer指定を解決し、取得元の履歴状態ごとに固定した`AudioInput`を共有する。同じ入力を読む複数ノードや履歴の変わらない描画では入力を共有する。追記・リセット・取得元の差し替えは新しいスナップショットにするが、PCMは不変ブロックのまま共有し、区間と参照だけを固定する。窓取得も必要なブロックを参照し、履歴全体・要求区間のPCMを再複製しない。過去の入力が参照するPCMは変更しない。Visual Moduleには`resolveAudioSource`を注入し、Player指定の解釈とスナップショットの所有をGlitch Studio側に保つ。

タイムラインの`timelineFps`と`timelineMotionBlur`は`TimelineRendererManager`のstatic optionsとして初期化時に確定する。変更時はUI側のPreviewRenderEngineが両プレビューをWorkerごと再生成し、キャッシュ・エフェクトの履歴・蓄積用GPUリソースを引き継がない。fpsとブラー設定の同時適用は1回にまとめ、再生成中の後続変更も最新値まで反映する。

プレビュー用のサンプル数はUIがプロジェクトと別に所有する。UIはプレビュー用Managerを作る際に`timelineMotionBlur.samples`をUIの選択値で上書きし、書き出し用Managerには保存されたプロジェクトのサンプル数を渡す。レンダラーはプレビュー専用のサンプル数フィールドやプロジェクトの既定値を持たない。

プレビューfps倍率は描画要求の頻度とフレーム境界を決める。UIは実効fpsをdynamic optionsの`previewFps`として送り、変更時は描画インスタンスとフレームキャッシュを破棄する。Worker自体の再生成は不要。動画書き出しでは呼び出し側が指定したfpsを露光時間の基準に使い、静止画とプレビューではstatic optionsの`timelineFps`を使う。ブラー無効・シャッター角0・サンプル数0/1の場合は`TimelineRenderer.renderAt()`で単発描画し、複数サンプル用の管理を経由しない。

ブラウザー版・Electron版のタイムラインプレビューは、Scene枠へ確定したモーションブラー適用後・表示処理前の最終画像を`TimelinePreviewFrameCache`へ複製する。キャッシュ画像は独立したGPUTextureで、既定では元の形式・float精度・premultiplied alphaを保持する。次の描画で更新される作業用画像の参照だけを保存しない。GPU完了後に開始時の内容世代が有効な画像だけを登録する。ヒット時もCanvasRendererを通し、表示設定・波形・ヒストグラム・要求されたシーク完了通知を維持する。

保存精度は`TimelineRendererManager`のstatic optionsの`frameCachePrecision`（`original`／`8bit`、省略時`original`）、容量は`frameCacheMaxBytes`（省略時0）で生成時に確定する。UIは編集ウィンドウごとの環境設定（既定は元の精度・2GiB、0で無効）から渡し、どちらの変更でも両プレビューをWorkerごと再生成する。キャッシュ・エフェクトの履歴・蓄積用GPUリソースは引き継がない。

8bit保存では既存の複製用描画パスの出力先を`rgba8unorm-srgb`へ変更する。乗算済みlinear RGBを保存時にencode・参照時にdecodeし、alphaは線形8bitで保持する。unpremultiplyせず、alpha=0の発光も保存範囲内で維持する。負値・1を超える成分は失われる。初回表示は元のfloat画像、キャッシュヒット時は量子化済み画像なので、表示・露出変更・波形・ヒストグラムの結果は異なる場合がある。露出・背景・表示変換は焼き込まず、通常の描画計算と書き出しの精度は変更しない。

使用量は幅×高さ×保存先形式のバイト数の合計で推定する。8bit保存は4byte/画素で、通常の`rgba16float`画像では容量が半分になるが、R/RG形式では必ずしも削減にならない。OS全体のVRAM使用量やドライバーの実割当量は計測しない。保存前・登録時にLRUで削除し、一枚で上限を超える画像は保存しない。編集・素材・生成音声・Scene・解像度・プレビューfps・データ精度・ブラー設定の変更で全消去する。選択や表示上の警告の変更では保持する。履歴依存エフェクトも一律にキャッシュし、ヒット時の履歴更新・復元は行わないため、ミスへの切替時や書き出しとの結果一致は保証しない。書き出しは上限0で動作する。

変形ハンドルはキャッシュ生成時に同じScene内のレイヤーの寸法・変形情報を保存し、後の選択変更でも画像の再評価なしで復元する。保存・削除で変化した連続フレーム区間と推定容量を約100msごとに`frameCache`で通知する。LRU順の更新だけでは通知せず、計測設定とは独立して動作する。

タイムラインのプレビューは、再生・シーク・一時停止とも`TimelinePreviewScheduler`へ渡す。CPU側の素材準備・評価・コマンド送信は直列に行い、送信済みでGPU完了待ちのフレーム数を静的オプション`previewFramesAhead + 1`件まで許可する。`previewFramesAhead`の省略時は1（合計2件）、0ではGPU完了まで直列に処理する。UIの環境設定は0〜3を受け付け、変更時はWorkerを再生成するため、旧フレームの処理とキャッシュは持ち越さない。小さなUIアニメーションがあるだけでGPU完了待ちが長くなる環境でも、先行を許可すると1件目の完了通知を待つ間に次の準備を進められる。待機要求は最新1件へ上書きする。進行中のフレームは通常のシークでは中断せず、音声時計・再生時刻はUI側で進め続ける。シーク先が表示されるまで描画済みの画像を保ち、進行中だった古い時刻の画像が一時的に表示されることは許容する。

プレビューの`timeDelta`（ms）は、今回のタイムライン時刻から直前にCPU側の評価・送信が成功した時刻を引いた値を使う。GPU完了後の後処理順や、省略された要求の時刻は基準にしない。同時刻の再描画は0、逆方向のシークは負の値をそのまま各エフェクトへ渡す。初回とスケジューラーの`clear()`後は0とし、初期化前の処理が遅れて完了しても基準時刻を引き継がない。モーションブラーではこの差をフレーム本来の経過時間として渡し、各サンプルの時間差は従来どおりサンプル間で求める。

両Managerの素材一覧とVisual Module Live PreviewのPlayer定義は、非同期factoryの`create(coreConfig, staticOptions, resources, signal?)`で受け取り、寿命中に変更しない。コンストラクターは非公開とし、factoryが`AssetTextures`の画像デコード・GPU転送を待ってから描画可能なManagerを返す。渡されたGPUDeviceはManagerが所有し、生成失敗・AbortSignalによる中断時もfactoryが回収する。中断時はデコード完了を待たずに生成待機を終了し、遅れて完了したデコードではGPUを使用せずBitmapだけを閉じる。CanvasからGPUを準備する`createManager()`と書き出しは、ともにこのfactoryを使う。`createManager()`は同期処理の`updateDynamicOptions()`で初期設定を適用してから返す。`assets`・`players`はdynamic optionsに含めず、更新時はUI側でManagerを破棄・再生成する。描画中の素材待機や更新要求間の世代管理は持たない。

GPUを所有するManagerが、最終表示とモーションブラーの全サンプルをsubmitした後に送信済みを通知し、`queue.onSubmittedWorkDone()`を待つ。画像キャッシュの登録・シーク完了通知・統計の集計は引き続き実際のGPU完了後に行う。GPU待機中の計測や変形情報は各フレームが保持し、後処理の完了順が入れ替わっても最新の変形情報を古い結果で上書きしない。途中の失敗や編集による中断でも送信済み処理を待ち、編集・Scene切り替え・失敗後の再試行は旧フレームのGPU処理を追い越さない。直接呼び出した`renderTimelineAt()`の戻り値も送信済み全フレームの完了を待つ。書き出し用の`renderTimelineFrame()`はこのスケジューラーを経由せず、呼び出し側が全フレームを順番に描画・エンコードする。

両Managerはstatic optionsの`enableStats`で計測の有無を決める。無効時は統計通知タイマーを作らず、Timelineの時計読み出し・動画計測コールバック、Live PreviewのFPS集計・TimingHelper・GPUメモリ追跡を停止する。TimingHelperは計測するデバイスのqueueだけをラップし、import時にGPUQueueのプロトタイプを変更しない。書き出しの`renderTimelineFrame()`は計測経路を使わず、書き出しWorkerも明示的に無効を指定する。

プレビューのヒストグラム・縦横の波形は、両Managerのstatic optionsの`enableWaveformAndHistogram`でまとめて制御する。`CanvasRenderer`は無効時に解析用インスタンスを生成せず、バッファ・pipelineの確保もcompute/render passも省く。通常のCanvas出力や計測の有効・無効とは独立し、エフェクトとして配置した波形・ヒストグラムには適用しない。書き出しWorkerでは常に無効を指定する。

表示用の露出は両Managerのdynamic optionsの`previewExposure`（EV、既定0）を`CanvasRenderer`へ渡す。乗算済みlinear RGBへ`2^EV`を乗算し、色域圧縮・解析・警告判定の後に黒・チェック背景をlinearで合成してsRGBへencodeする。GPU方式・CPU方式は同じ出力パスを使う。`previewBackground`は表示専用で、透明なSDR書き出しではnull、不透明出力では黒背景を使う。チェック背景は表示用に所有するlinear画像で再描画し、ノード・履歴・解析を進めない。背景の種類や位相は全ての解析・警告判定から除外する。`analysisValueScale`はsRGB・Linear・EV（0 EV=0.18）、`analysisValueRange`は各方式の単位での`{ minimum, maximum }`を独立して指定する。変換後の値を範囲で正規化し、minimum > maximumなら軸を反転する。同値（float32への丸め後も含む）なら集計を省いて空表示にする。露出・背景・解析設定はキャッシュへ焼き込まず、書き出しへ暗黙に反映しない。[色空間の規約](../../../docs/color-management.md)を参照。

`analysisImageSource`はヒストグラム・縦横の波形に共通の解析画像で、`original`（既定）と`previewAdjusted`から選ぶ。警告の判定対象からは独立させ、RGB以外の解析対象では元画像へ固定する。`PreviewAnalysisImageTransform`は集計時に元のfloatサンプルへ調整を適用し、背景・警告・表示clamp・encodeを通さない。中間の全画面画像やHALFへの追加の量子化は不要。色域境界LUTは主表示と解析で共有し、uniformバッファは別にして同じencoder内で互いの設定を上書きしない。汎用の波形は`GpuImageSampleTransform`を受け取り、Glitch Studioの表示設定へ依存しない。

`analysisTarget`はRGB・Alpha・Vector X・Vector Y・Vector Lengthを選び、両Managerから`CanvasRenderer`へ同期する。RGBは従来の未乗算・alpha重み付けを使い、他の対象はA・R・G・`length(RG)`を保存値のまま重み1で解析する。数値データの表示は白で、alpha=0や値域の下端も表示する。数値データはLinearに限り、sRGB・EVの指定はGPUへの設定境界でもLinearへ補正する。表示範囲はこの補正によって変更しない。対象選択と集計用の値・重みの計算は、Waveformエフェクトも利用する`@gs/shared/utility/image-analysis.ts`・`@gs/shared/gpu/image-analysis.wgsl`へまとめる。

`PreviewImageAnalysis`は解析Canvas・直近の借用入力・High-res用の所有画像を管理する。両Managerの`setHighResolutionImageAnalysis(true, settings)`は最初の要求でだけ入力を同じ寸法・形式へ`textureLoad`で複製し、その後の要求では保持画像を全画素で再集計する。COPY_SRCを持たないR/RG/RGBA・float32入力も表示変換やRGBA16への量子化を通さない。画像の選択・露出・有効な色域圧縮を変えたときも、元の保持画像へ要求内の調整を適用する。背景やその位相は保持しない。シーンの編集による`CanvasRenderer.clear()`は借用参照だけを破棄し、保持画像を残す。falseの要求・破棄では所有画像を解放する。通常入力がなければfalseを返し、後のフレームを代わりに保持しない。

High-res中の`analysisPaused`は通常解析だけを止める。保持側は所有画像がある間も通常解析を止め、明示的な再解析は休止状態にかかわらず実行する。CPU表示では通常フレームの予約を主Canvasへ限定し、再解析は解析Canvasだけを予約・転送する。保持開始前の未完了転送を無効化し、返り値はGPU完了・CPU画素送信の後に返す。シーン変更でCPU予約を取り消した場合も、同じ保持画像で再試行する。対象・方式・範囲は各要求の`PreviewImageAnalysisSettings`で固定し、UI側が間引きと反映済み設定を管理する。

波形のCanvas寸法はUIが渡す`analysisWaveformCanvasSizes`に従い、通常時・High-resとも表示実寸×DPRにする。`GpuWaveform`の集計ビン数もCanvasに合わせる。位置ビンは表示領域内のサンプル数まで、値ビンはGPUのバッファ上限までとし、Canvas自体は最大テクスチャ寸法へ収める。通常時の入力は長辺1024以下を基準にし、位置方向だけはズーム後の表示に必要な数まで増やす（元解像度が上限）。両Managerの`setWaveformDisplay()`は`PreviewWaveformDisplaySettings`のCanvas寸法・表示領域を受け取る表示専用の更新で、タイル描画・履歴・キャッシュを無効化しない。表示中のManagerだけ`CanvasRenderer.refreshImageAnalysis()`で最後の完成画像を描き直し、主Canvasの描画やノード評価を行わない。High-resでは`PreviewImageAnalysisSettings`へ同梱して保持画像を再解析する。

`analysisWaveformViewports`は縦横別の正規化した表示領域（左上原点）を保持し、nullなら全体を表示する。`getPreviewWaveformViewportRanges()`が波形の向きに応じて画像位置の`positionRange`と値の`valueWindow`へ変換し、UIの目盛りにも同じ変換を使う。位置範囲外の画素は読み出し前に除外し、境界にかかる画素セルは含める。値は元の解析範囲でclampした後に表示窓で切り出し、窓の端へ再clampしない。CanvasのCSS拡大を行わず、現在のビン数で再集計する。ヒストグラムの表示領域は変更しない。

固定小数点の集計経路は`@gs/shared/utility/image-analysis-accumulation.ts`の上限判定で選ぶ。最大重み65535×65537サンプルがu32上限と一致するため、ヒストグラムは全サンプル数、波形は`ceil(位置サンプル数 / 位置ビン数) × 直交方向サンプル数`が65537以下なら従来の直接集計を使う。直接経路では一つのu32バッファを集計・描画で共有し、結果統合をdispatchしない。High-resの小さい入力も直接経路になり、通常モードでも極端に少ない位置ビンなら分割経路になる。

波形を切り出す場合の最大位置サンプル数は`getWaveformMaximumPositionSamplesPerBin()`で求める。表示領域の幅を反映し、ビン境界にかかる画素とfloat32の丸めを見込んだ上限を使う。集計バッファの予算計算と経路選択は同じ上限式を使う。

上限を超える場合だけ8192サンプル単位のu32部分和をfloatへ集約する。分割用pipelineと追加バッファは遅延生成し、直接経路へ戻る際には追加バッファとそれを参照するbind groupを解放する。波形はpipeline定数で直接／分割と位置・値の切り出しの有無を特殊化し、直接経路のサンプル処理では部分和番号の計算、全体表示では切り出しの計算も省く。この共通波形処理は作品内のWaveformエフェクトにも適用される。波形の強度はサンプル数・集計ビン数と表示領域の比率で補正する。

有効時のタイムラインのプレビュー計測は`performance.now()`の実経過時間を使い、フレーム全体・動画取得待ち・動画取り込みのCPU側処理・GPU完了待ちを分ける。フレーム全体は処理開始からGPU完了（CPU表示方式では読み戻し・RGBA変換・UIへの送信）までで、Scheduler内の順番待ちとUIでのCanvas描画は含めない。動画取得はファイル読み取り・初期化・デコード・キャッシュ待ちを含む。取り込みは変換・転送API・submitのCPU側時間で、GPU完了待ちは最終submit後の残りのキュー待ちであり、どちらもGPUの総実行時間ではない。計測のためだけのGPU同期や画像読み戻しは追加しない。

動画レイヤーの計測を子Scene・複数レイヤー・モーションブラーの全サンプルについて一つの出力フレームへ合算する。取得・取り込みのキャッシュヒットは省略した処理を0として扱う。書き出し・失敗・編集で無効になったフレームは集計しない。`TimelinePreviewStatisticsCollector`は通知間の正常完了フレームから平均と項目ごとの最大値を作り、約100msごとに`telemetry`で通知する。Scene・編集世代の異なるフレームは混ぜず、UI側も古い世代を採用しない。新しい完了フレームがなければ通知せず、破棄時に通知タイマーを停止する。

注意する必要があるのは、すべてのサブシステムは公平だということです。

TimelineはVisual Moduleを使用し、Visual ModuleはEffectを使用するという依存の階層構造自体はあるが、それは「Glitch Studioにおいてはタイムラインがメイン機能であり、タイムラインがすべてをk管理する」などということは意味せず、Glitch Studio自体の設計とは全く関係がない。

プロジェクト共通のAutomation Graphは両Managerのプロジェクト状態として同期する。Timeline Managerは保存用Sceneと評価用Sceneを分け、Glitch Studio sharedで各レイヤーの定義へ共通定義を加えてからTimelineへ渡す。共通定義の変更時は既存のTimeline描画インスタンスを破棄し、停止中の同一時刻でも最新の曲線を評価する。カメラ・Transform・合成設定・音声入力にも同じ一覧を使う。Live Preview Managerは公開パラメータへの入力評価にだけ共通定義を渡し、Visual Module内部には渡さない。音声試聴と書き出しも評価用Sceneから音声計画を作り、所属Sceneの時計を維持する。
Custom Shader Effectの初期定義はManager生成時の`resources.customShaderEffects`へ渡す。更新時は`customShaderEffects`差分で定義と補正済みのVisual Module・Timeline・Automation Graphのスナップショットを一括反映する。`custom-shader-effects.ts`が注入された組み込み一覧と組み合わせ、全描画インスタンス・履歴・キャッシュを作り直す。Worker・Manager・GPUDevice・素材・Player・Canvasは維持する。書き出しも同じ初期資源一覧から生成し、Worker固有の登録処理は持たない。

Visual Module Live Previewは同期の描画ループから`VisualModuleRenderer.tryPrepare()`で準備を開始・確認する。コンパイル・動画取得等の準備中は同じ評価時刻・入力を保持し、準備が完了したフレームを描画してから最新の時刻へ進む。待機中の経過時間・ポインター移動は次の描画へ引き継ぐ。編集・解像度変更・履歴リセット・停止では保留中の評価結果を破棄する。準備完了後の再開処理は登録せず、次の描画コールバックで確認する。タイル実行のPromiseは描画ループが完了まで保持し、その間の描画を重ねない。

環境設定の`effectRenderTileDivisionLevel`はVisual Module Live Preview・TimelineのEffect/Visual Moduleレイヤー・書き出しへ共通で渡す。0は従来の一括送信を維持し、1〜4はEffect Rendererが各Render Passを4〜256タイルへ分割して完了を待つ。最終Canvas・解析・キャッシュの表示経路は完成画像を受け取る。タイル実行中のPlayer VideoFrame更新は最新の一枚だけ保留し、借用中のフレームを閉じたり別ノードへ異なるフレームを渡したりしない。配線・解像度などの構造変更や停止による古い世代の結果は表示しない。通常パラメータの値変更では実行中のタイル描画を中断せず、最新値だけをフレーム完了後に反映する。公開入力・カスタムパラメータも同様に扱い、描画インスタンス・出力寸法・履歴を維持する。Timelineもノードとカスタムパラメータの変更を完了境界で反映し、旧内容のキャッシュ・完了通知を無効化しつつ、待機中の最新シークは維持する。Compute Passは分割しない。

## Canvasの色空間検証

`probe:canvas-color-output`は、アプリの設定を変更せずに独立した検証画面を生成する。WebGPUのfloat出力の色空間対応・負値と1超の保持・Canvas 2Dへの色変換を調べ、ランタイムと画面の大まかな能力判定をJSONで出力する。ChromeとElectronは、一時プロファイルと非表示のウィンドウでそれぞれ起動する。

`CHROME_PATH`／`ELECTRON_PATH`で実行ファイルを指定するか、`--executable`を渡して以下を実行する。

```sh
pnpm --dir packages/glitch-studio/renderer probe:canvas-color-output --runtime chrome
pnpm --dir packages/glitch-studio/renderer probe:canvas-color-output --runtime electron
```

画面を目視する場合は`--serve`でローカルサーバーだけを起動し、表示されたURLを対象ブラウザーで開く。sRGBの赤とP3の赤を左右に並べ、8bitの対照表示と各float表示を比較できる。物理モニターの色再現精度は、数値検証とは別に確認する。

```sh
pnpm --dir packages/glitch-studio/renderer probe:canvas-color-output --serve
```

`canvas-color-output.gpu.test.mjs`は同じ検証を自動実行する。対応する実行ファイルの環境変数がない場合はskipする。WindowsのChrome 157／Electron 45.2.1の結果と制約は[色空間の規約](../../../docs/color-management.md#広色域canvasの検証)を参照。

`--preview`を付けると、実際の`CanvasRenderer`を使うWorkerの検証へ切り替える。転送したOffscreenCanvasへの広色域出力・表示変換・CPU表示とSDR書き出しのsRGB維持を調べる。この検証も上記の自動テストで両ランタイムに対して実行する。

```sh
pnpm --dir packages/glitch-studio/renderer probe:canvas-color-output --runtime chrome --preview
pnpm --dir packages/glitch-studio/renderer probe:canvas-color-output --runtime electron --preview
```
