# Glitch Studio UI

## OSからのファイルオープン

Electron版の起動時は`App.vue`から`desktop.takeStartupFile()`を呼び、プロジェクトなら保存可能なハンドルで開き、画像・動画なら`app.ts`の`newProjectFromMediaPath()`で新規プロジェクトを作ります。通常起動と読み込み失敗時はダッシュボードを表示します。`utility/open-media-file.ts`の`openMediaFileFromPath()`が取り込み中の操作ロック・待機表示と埋め込み／外部参照設定の適用を担当し、デコードは`external-assets.ts`の既存経路へ渡します。素材のパスをプロジェクトの保存先として扱いません。対応形式とOS登録方法は[Electron版README](../desktop/README.md#画像動画をosから開く)を参照してください。

## コンポーネントの実装

メンテナンスしやすさを保つため、HTMLをセマンティックにしたり、アクセシビリティを考慮したりする必要はありません。基本的にdivやspanタグを使い、aria属性・role属性は不要です。

Webサイトではないので、スクリーンリーダーには対応することはありませんし、検索エンジン最適化を行うこともありません。

特別な理由がない限りoverflow: hidden;ではなくoverflow: clip;を使ってください。

styleタグ内でCSSを一行にまとめて書かないでください。

必ずCSS Modulesのクラス指定でセレクタを使用してください。divやspanなどタグ名のセレクタを使わないでください。

`src/style.scss`のリセット・テーマの初期値・ボタン系の基礎スタイルは`@layer base`に置き、各Vueコンポーネントのスタイルはレイヤーなしで定義する。通常の宣言ではコンポーネント側が優先されるため、開発時とビルド後のCSS読み込み順に依存しない。`._shadow`・`._monospace`など明示的な効果を付けるユーティリティはレイヤー外に置く。`!important`ではレイヤーの優先順位が逆転するため、基礎スタイルには追加しない。

title属性を使わないでください。v-tooltipディレクティブを使用してください。

プロジェクトの操作はCommandを通し、Undo/Redoとレンダラー同期を同じ変更通知から行う。

## ポップアップの配置

`ui.popup()`で登録したポップアップは、`App.vue`の一覧全体をTeleportし、各ポップアップの実DOMを`body`直下へ配置する。モーダルだけでなく、選択メニュー・コンテキストメニュー・ツールチップ・入力補完もこの描画先を共有する。

テンプレート内で直接宣言するモーダルは、呼び出し側で`body`へTeleportする。Color ramp・角度入力・XY入力などの既存のTeleportも維持する。ポップアップ一覧を囲むDOM要素を追加せず、各モーダルのルートを同じ階層へ配置する。異なる階層でfocus trapを切り替えると、背景内部に設定した`inert`が最後のモーダルを閉じた後も残る場合があるため。

## UIの翻訳

画面の固定文言は`locales/en-US.json`と`locales/ja-JP.json`に定義し、`src/i18n.ts`の`i18n.ts`から参照する。画面・機能固有のキーは`_Timeline`など`_`で始まるオブジェクトにまとめる。件数や名前を含む文は`{count}`などのプレースホルダーを使い、`i18n.tsx`で補間する。翻訳ごとに語順を変えられるよう、文章を断片に分割して連結しない。

翻訳のキー構造は英語辞書から導出する。キーと補間パラメータは両言語で揃える。初回起動時のダイアログ、または環境設定の「言語」で日本語・英語を選択できる。環境設定では「適用」で保存し、キャンセル時は変更しない。選択した言語はlocalStorageの`locale`に保存し、新しく開いた・再読み込みしたウィンドウに反映する。既存画面の辞書は切り替えず、アプリ全体で言語を固定する状態も持たない。言語が未設定のまま複数画面を同時に開いた場合は、それぞれに初回ダイアログを表示する。`src/i18n.ts`は辞書の読み込み・翻訳・言語設定の保存を担当し、UIに依存しない。言語選択ダイアログと適用タイミングの案内は`src/locale-settings-ui.ts`が担当する。

言語以外の環境設定は`preferences:<項目名>`のキーごとに保存する。各画面は起動時に一度だけ保存値を読み込み、他の画面での設定変更は自動同期しない。設定ダイアログを開き直す場合も、その画面が保持する設定を使用する。変更した項目だけを保存し、同じ項目を複数画面で変更した場合は、最後に保存した値を新規画面・再読み込み時の初期値とする。バックアップの有効・無効、間隔、保持期間はそれぞれ独立した項目として保存し、レイアウトは整合した一つの値として保存する。GPUのデータ精度と中間テクスチャ形式を含め、変更は操作した画面だけに反映する。言語の選択値は設定ダイアログを開いたときに保存値から取得し、保存時にも保存値と比較する。言語の辞書の切り替えは、新規画面・再読み込み時に行う。

エフェクトのパラメータ定義やユーザーが編集・保存する名前、コード・形式名・単位は、このUI文言の翻訳対象に含めない。

## プロジェクト共通のAutomation Graph

ワークスペースパネルの種類から「プロジェクト共通のAutomation Graph」を選ぶと、曲線の作成・複製・参照名変更・削除・時間軸変更・点の編集ができる。操作はCommandを通し、保存・Undo/Redo・レンダラー同期へ反映する。パラメータの選択メニューはローカルとプロジェクト共通を区分し、共通定義は参照元からも曲線編集ウィンドウを開ける。削除された参照と未選択は表示を区別する。

参照名は共通定義の中で一意にする。名前変更ダイアログは`GRAPH()`内の参照名を自動変更しないことを案内する。曲線の再生設定は共通定義ではなく参照元のパラメータに保存する。

## Timelineのプレビュー再生・BAKE

環境設定の「レンダリング」にある「タイムラインプレビューの先行フレーム数」は、処理中の1フレームに追加する先行数を0〜3で指定します。既定値は1（合計2フレーム）、0では各フレームのGPU完了を待ってから次を処理します。端末・編集ウィンドウの環境設定として保存し、プロジェクトには含めません。変更時は`updateStaticOptions()`でTimelineのWorkerを再生成するため、プレビューの初期化とフレームキャッシュの消去が発生します。Scene・現在位置・再生状態は維持し、Visual ModuleのWorkerは再生成しません。

通常再生では`TimelineAudioPreview.currentTime()`が音声出力のtimestamp対から現在時刻を補間し、`PreviewPlaybackController`は毎RAFで表示対象フレームの変化を判定します。FPS制限をRAF間隔でも重ねると時計の位相差・浮動小数点の誤差で描画機会を逃すため、描画要求は表示フレームの変化だけで制限します。明示的な`refresh()`は編集・Worker復帰のため同じ時刻でも再描画します。

TimelineのBAKEは`PreviewPlaybackController`が現在位置からScene終端までのフレーム進行と中止を管理し、`TimelineRendererManagerController.renderTimelineAtAndWait()`が既存の`frameRendered`通知でGPU描画完了を待ちます。通常シークのスピナーやキャッシュ済み通知の省略とは独立し、BAKEでは毎フレーム完了通知を要求します。通常操作・設定更新・編集・Worker破棄で待機を解除し、レンダラーにはBAKE専用の処理を追加しません。挙動は[タイムライン](../../../docs/timeline.md)を参照してください。

## Timelineのエクスポート

エクスポートダイアログの解像度はSceneの基準サイズ、フレームレートはプロジェクトのTimeline FPSに対し、0.25x / 0.5x / 1x / 2x / 4xから選ぶ。カスタムでは幅・高さとFPSを直接入力する。MP4では奇数の辺を1px増やして偶数にする。カスタム解像度は書き出し対象Sceneの基準サイズとして使い、その画角で描画する。プロジェクトや子Sceneの基準サイズは変更しない。

Scene・動画／静止画・形式・品質・解像度・FPS・時間範囲と未選択のカスタム入力値を、書き出し開始時またはダイアログを閉じた時にCommandで保持する。プロジェクト保存・バックアップに`exportSettings`として含め、次回表示とファイル再読込後に復元する。倍率は確定した寸法やFPSに置き換えず、再表示時の基準設定から計算する。書き出すSceneが未選択なら先頭のSceneを選ぶ。前回のSceneが削除されている場合は現在のScene（なければ先頭のScene）とその全時間範囲へ戻す。

`ApplicationActivity.acquireExport()`で保存先選択から音声準備・描画・エンコード・ファイル書き込み・プレビュー復帰までをエクスポート中として扱う。完了・キャンセル・失敗のいずれでも解除する。Electron版はその間のウィンドウ終了・アプリ終了・再読み込みを禁止し、Web版はブラウザー標準の終了確認を要求する。

描画開始前に`AppContext.suspendPreview()`で映像プレビューを破棄し、音声モニターの描画・FFTを休止する。音声Workerの休止受理とVueの表示更新を待ってから書き出しへ進む。音声の再生状態とは独立した一時状態で、パネル・Canvas・設定・音声履歴は保持する。成功・失敗・キャンセル後は映像プレビューの再初期化を待ってから音声モニターを復帰する。先行する初期化が遅れて完了しても、その途中に入った新しい休止は解除しない。

GPU処理を止めたCanvasも画面合成に影響するため、休止中はワークスペースを非表示にし、プレビューCanvasを合成対象から外す。コンポーネントはアンマウントせず、レイアウト設定を保持する。別ウィンドウへ移したプレビューとパネルも内容を非表示にするが、タイトルバー、bodyへTeleportする進捗・キャンセルUIは表示を続ける。復帰時は現在の表示先に最新のCanvasを付け直す。書き出しの解像度・FPS・品質やエンコーダーのバックプレッシャーは変更しない。

進捗UIも毎画面の合成がエンコード経路と競合する環境があるため、ドットは静止表示にし、進捗バーの幅をアニメーションで補間しない。Workerからの進捗通知で数値とバーを更新し、キャンセル操作は常時受け付ける。

## Visual Moduleのエクスポート・インポート

環境設定のVisual Module Editorにある「追加したノードを自動接続する」で、エフェクトノード追加時の自動接続を切り替える。既定値は無効。有効時は現在の主出力の接続元（副出力ポートも含む）を追加ノードの主入力へ引き継ぎ、追加ノードの主出力をVisual Moduleの主出力へ接続する。それぞれ接続可能な場合だけ変更し、明示的に指定されたパラメータは優先する。登録済み・インラインの両方で適用し、Undo/Redoでは設定変更にかかわらず追加時の配線を復元する。素材ドロップによる追加は既存の配線を維持する。

`GsVisualModuleEditor`はファイル・Assetのドロップ受付と表示を担当し、親が渡す`VisualModuleAssetDropActions`で保存先へ反映する。登録済みとインラインの両方で`utility/visual-module-drop-actions.ts`を使い、画像・動画・音声からImage・Video・Audio Waveformノードを通常ノード一覧の末尾へ追加する。ノード生成は`visual-module-asset-node.ts`、Asset・Player・ノードの一括追加とUndo/RedoはCommandが担当する。既存の配線と出力接続は変更しない。

`gsvm.ts`は`.gsvm`（MessagePack）の依存収集・バイナリ変換・取り込み準備を担当する。ノードの値と公開パラメータの既定値・設定ツリーから静的な素材／Player参照を収集し、取り込み用のプロジェクト内IDを生成する。素材参照の加工式は無効化中や基準値がnullの場合も含めて転送を拒否する。元PCのパスや利用側のレイヤー／Visual Module Live Previewの状態は保存しない。

`utility/visual-module-file.ts`が選択・ダウンロード・エラー表示を担当する。共通のVisual ModuleエディターはOtherタブから`requestExport`を通知し、登録済み／インラインそれぞれの親が対象名とプロジェクトを渡す。ImportはApp.vueのFile → Import → Visual Module (.gsvm)、または登録済みVisual Moduleの選択メニューから同じ処理を呼び出し、`importVisualModule` Commandで依存リソースごと一括追加する。ファイル選択・読み出しの間に`ProjectContext.load()`の世代が変わった操作は破棄する。

`visualModuleRegistration`の通知は追加・削除後の最終値を両レンダラーへ送る。同じターンの内部編集は登録データへ吸収し、UndoでVisual Module Live Preview対象が消えたときはTimeline表示へ戻す。

## Workspaceのパネル表示

タイトルバーのWindowメニューは`workspacePanelChoices`から全パネル種類を表示し、選択した種類の新しいパネルをブラウザー／OSの別ウィンドウで開く。`GsWorkspacePanelWindow.vue`は元のVueツリーからTeleportするため、プロジェクト状態とprovideを共有する。既存のworkspace配置は変更せず、ウィンドウを閉じるとパネルを破棄し、親画面の終了・再読み込みでも子ウィンドウを閉じる。ポップアップがブロックされた場合はエラーを表示する。

Electron版の通常の別ウィンドウは`GsDetachedWindowFrame.vue`でタイトルバーとコンテンツを分ける。メイン画面と共通の`GsWindowTitlebar.vue`でアイコン・パネル名・ドラッグ領域を表示し、OSの操作ボタンを避けた領域へ配置する。既存パネルを切り離す場合も同じ枠を使い、元へ戻す際にはパネルのインスタンスを保ったままタイトルバーだけを隠す。Web版とDocument PiPではタイトルバーを表示しない。

別ウィンドウのパネルは`WorkspaceController.windowPanels`に実行時だけ登録する。パネル表示の探索では、新しく開いた別ウィンドウを同じ種類のworkspace内パネルより優先する。Timelineの詳細パネルを別ウィンドウで開いた場合も選択内容を表示でき、別ウィンドウのTimelineからworkspace内のAssetsや詳細パネルを開ける。閉じた後は残ったパネルを再び対象にする。

計測設定`preferences.renderingStatsEnabled`の既定値はtrue。App.vueのフッターのStatsボタンから両プレビューの計測をまとめて切り替え、preferencesに保存して再起動後も復元する。GPUデバイスの計測機能とリソース追跡の有無を変更するため、既存のstatic options更新でWorkerを再生成する。計測無効時はStatsパネルの定期サンプリングも停止し、Live PreviewのフッターFPSは実測値の代わりに設定上限を表示する。プロジェクト・Undo履歴には保存しない。書き出しWorkerはプレビュー設定にかかわらず`enableStats: false`を指定する。

解析モニターの設定`preferences.analysisMonitorsEnabled`の既定値はtrue。App.vueのフッターのAnalyzeから、TimelineとVisual Module Live Previewのヒストグラム・縦横の波形と、音声波形・スペクトラム・スペクトログラムの監視パネルをまとめて切り替える。Statsとは独立した設定で、preferencesに保存して再起動後も復元し、プロジェクト・Undo履歴には保存しない。

映像側はstatic optionsの`enableWaveformAndHistogram`へ反映してWorkerを再生成し、無効時は解析用GPUリソースの生成・集計・描画を省く。書き出しWorkerでは常に無効にする。音声側は`AudioPreview.setAnalysisEnabled()`でFFT等の解析・GPU描画ループを止め、パネルに無効の案内を表示する。Canvas・設定・PCM履歴は維持し、再度有効にしたときは同じパネルで復帰する。音声再生・基本の音量メーター・作品内の音声解析エフェクト・通常のプレビュー描画は継続する。

Analyze設定と書き出し等の一時休止は別に保持し、音声モニターはAnalyzeが有効かつ休止していないときだけ描画する。休止中にAnalyzeを有効にしても直ちに描画せず、Analyzeが無効のままなら書き出し終了後も停止を維持する。

Statsパネルは表示中のプレビューに追従する。Timelineではフレーム全体・動画取得待ち・動画取り込み（CPU）・GPU完了待ちをmsで表示し、約100msごとの完了フレームの平均をグラフにする。凡例の括弧内は各項目の最大値で、同一フレームの値とは限らない。全体には個別の待ち時間が含まれるため、四項目を足し合わせない。凡例のツールチップで各計測範囲を確認できる。Visual Module Live Previewは従来のGPU移動平均を表示し、表示モード切り替え時にグラフの履歴を分ける。TimelineのScene変更・Worker破棄時には古い統計を消す。

アプリ内のHTML Drag and Dropは`composables/useDragSession.ts`を使う。`utility/drag-and-drop.ts`が型付きデータのスナップショット・開始元の識別・終了処理を所有し、dragoverでも同じセッションのデータを参照できる。GsTimeline、GsDraggable、GsWorkspacePanel、GsWorkspaceDivider、GsAssetはドラッグ状態をこの仕組みへ委ねる。操作ごとの移動条件や配置計算、Command・preferencesへの反映は各コンポーネントが所有する。APIと寿命の詳細は[UIのドラッグセッション](../../../docs/drag-and-drop.md)を参照。

`WorkspaceController`をworkspaceの所有元で生成し、`workspaceControllerKey`でprovideする。タブ選択はコントローラーが実行時状態として保持し、非表示でアンマウントされたタブも選択できる。折りたたみ状態は従来どおりpreferencesのworkspace定義へ保存する。

`revealPanel({ contentType, sourcePanelId })`は、操作元を隠す候補を除外してパネルを開き、対象ID（候補なしならnull）を返す。共通祖先のタブで別の枝に属する候補は対象外。sourcePanelIdがnullの場合は全体ドロップなど操作元パネルのない要求として扱い、別タブも候補に含める。指定されたパネルIDが存在しない場合は何もしない。必要なタブ切り替えと折りたたみ解除の合計回数が最小の候補を選び、同点ではツリー順を使う。探索・変更計画は`utility/workspace-panel-reveal.ts`の純粋な関数が担当する。

Timelineはレイヤー・クリップ・キーの選択操作から表示を要求する。同じ対象の再選択でも開き、範囲選択は確定後に開く。選択状態の監視で開き続けないため、手動で閉じたパネルは次の選択操作まで閉じたままになる。Teleport先は固定DOM IDではなく、コントローラーの`panelTargets`へパネルIDで登録した要素を使う。

`GsTimeline.vue`は選択状態・選択の検証・ショートカットと、詳細パネルの表示先を管理する。`GsTimeline.Inspector.vue`は選択から表示対象を解決し、`GsTimeline.Inspector.Keyframe.vue`・`GsTimeline.Inspector.Clip.vue`・`GsTimeline.Inspector.Layer.vue`がそれぞれの詳細編集をCommandで行う。選択変更とクリップ・キー削除は親へ通知し、パネルを閉じても同じ選択とショートカットを維持する。通常キーの編集対象は`utility/timeline-keyframe-edit.ts`で共通に解決する。素材選択・エフェクト追加のピッカーはタイムライン本体と共用するため親が所有し、Inspectorは対象のIDを渡して要求する。

`composables/useTimelineViewport.ts`は表示範囲・DOMの実測寸法・座標変換・目盛り・ズーム・パン・再生追従を管理する。座標と目盛りの計算は既存のutilityを使い、ポインター時刻の整数化はシークなどの操作側で行う。`composables/useTimelineInteraction.ts`が選択・移動・シークの所有権とキャンセル関数、ドラッグ後のクリック抑止を保持し、その操作中の状態をViewportへ渡してパンと追従を止める。表示範囲の保存とリスナー・ResizeObserverの解除はcomposableのスコープ終了時に行い、親の`onBeforeUnmount`でCUEが戻した位置を次の表示へ引き継ぐ。表示状態はプロジェクトの保存・Undoの対象にしない。

`composables/useTimelineMarqueeSelection.ts`は仮想一覧の境界計測・再計算・選択確定を担当する。pointerup後も最後の計測が終わるまで操作の所有権を保持し、レーン構成・寸法・Sceneの変更やスコープ終了でキャンセルする。キャンセル済みの計測結果は採用せず、その完了で次の操作を解除しない。

`composables/useTimelineSelectionDrag.ts`は移動・トリムのしきい値判定、現在のViewportでの座標変換、スナップ表示、mergeKeyとポインター追跡の寿命を担当し、同じ排他制御でシークも扱う。`utility/timeline-drag-actions.ts`はクリップ・グループ・キー・字幕ごとの開始時の対象と制約を準備し、共通ドラッグへCommandの適用関数を渡す。計算は既存のutility、変更は既存のCommandを使い、選択状態そのものは`GsTimeline.vue`が引き続き所有する。

`utility/timeline-source-actions.ts`は素材・Sceneの選択、クリップ追加・素材差し替え、レイヤー追加メニュー、グループの子孫を含む素材長の読み込みを担当する。`utility/timeline-selection-edit-actions.ts`は選択対象のコピー・切り取り・削除と、コピー内容の種類に応じた貼り付けの準備・Command適用を担当する。ダイアログ・素材情報の読み込み・選択更新・エラー表示は引数で受け取る。非同期処理の完了後はScene定義・素材Blob・対象クリップ・空き区間を各操作に応じて再確認し、破棄済みのパネルや別プロジェクトへ結果を適用しない。

タイムラインとオートメーショングラフはDOMの`copy`・`paste`・`cut`イベントを`utility/editor-edit-events.ts`で受け、Delete・Backspaceは同じ選択削除へ接続する。入力欄・contenteditable・通常の文字選択の操作は標準動作へ委ねる。コピー内容は従来どおりタイムラインの共有メモリとグラフ各エディタ内のメモリに保持し、OSクリップボードへデータや識別子を書き込まない。切り取りはコピーが成功した対象だけを削除し、正規化グラフの固定端点は切り取らない。

ヘッダーのCopy・Paste・Cut・DeleteボタンはElectron版に限って表示する。`useHeaderEditActions`は選択状態から有効・無効を決め、入力先のフォーカスを保持・復元してElectronの編集コマンドを呼ぶ。copy・paste・cutはネイティブのDOMイベント経由で各エディタへ届く。非編集要素にDeleteの標準DOMイベントは発生しないため、エディタの削除はキーと同じ削除関数へ接続し、テキスト入力欄の削除はElectronへ委ねる。ブラウザ版でもネイティブのショートカットは利用できる。

## 手動シークの描画待ち

停止中の手動シーク（フレーム送り・同時刻へのシークを含む）では、要求IDを付けて描画を要求し、プレビュー中央にスピナーを表示する。`frameRendered`は実際に描画した最新要求について、最終出力とモーションブラー全サンプルのGPU処理完了後にだけ発行する。Controllerは要求ID・時刻・Scene・状態の世代を照合し、シーク中の編集では同じIDを再描画へ引き継ぐ。再生開始・別プレビューへの切替・Scene切替・エラー・Worker破棄で待機表示を解除する。通常の再描画・再生中のシーク・タイムライン再生では、完了待ちの手動シークがない限り通知を要求せず、毎フレームの通信を追加しない。

## プレビューのレイヤー変形

`GsPreviewTransform.vue`は、停止中のTimelineで選択された単一レイヤーの合成設定を編集する。同じレイヤー内の複数クリップ・キーの選択も対象とし、選択は`getTimelineEditorState()`でタイムラインと共有する。音声・無効なレイヤー・現在時刻にクリップや出力がないレイヤーは対象外。プレビューから別レイヤーへの選択変更は行わない。

枠は合成前の画像の基準枠を表し、透明な余白を含む。テキスト・シェイプの基準枠はSceneサイズで、出力テクスチャには枠外の画素も含み得る。専用の文字・形状編集ではない。枠内で移動、角で比率固定の拡縮、辺で片軸拡縮、外側のハンドルでoriginを支点に回転する。通常の拡縮は対角・対辺固定、Altでorigin固定、Shiftで15度刻みの回転。反転済みの符号を維持し、ドラッグでゼロを跨がない。ゼロ倍率からはフッターのReset scaleで復帰できる。

フッターにはレイヤー名・合成前の出力解像度と、画面端へのスナップ（CSS px基準）を切り替えるボタンを置く。解像度はプレビュー倍率適用後の実テクスチャ寸法で、変形用の基準枠とは分離する。定数出力では解像度を表示しない。プレビューのメニューからハンドル表示と角の縦横比固定を切り替える。中ボタンドラッグは表示位置だけを動かし、ホイールはポインター直下の位置を固定してズーム、Center Viewは表示位置を中央へ戻す。これらはプロジェクトの変形値を変更しない。

literalは値を変更し、キーフレームは現在のScene時刻（最寄りの整数ms）へ追加・同時刻のキーを更新する。式・automation・環境変数の項目は表示のみ。位置が編集できない場合もAltによるorigin固定の拡縮は可能。変わらない項目にはキーを追加しない。

`preview-transform.ts`が操作時の座標計算・スナップ、`timeline-transform-edit.ts`がキーの準備・更新を担当する。`editTimelineLayerTransform`は位置・倍率などを一括検証・適用する。`UndoRedo.beginEdit()`は描画更新を通知しながら、確定時に一履歴だけを作る。Esc・pointercancel・ウィンドウ切替・選択やSceneの変更では取消し、開始時の値と既存Redoを保つ。外部のCommandは先にセッションを確定し、プロジェクト読み込みは状態交換前に取り消す。

Workerは表示対象だけを購読し、ポインター移動による更新はrequestAnimationFrameへまとめる。操作中の枠はUIで計算し、Workerの往復を待たない。操作終了時は差分同期をflushして待機する世代を記録し、その世代以降のプレビュー応答でドラフトを解除する。加工式によってドラフトと描画位置が異なる場合も、座標の一致は待たない。解像度は既存の変形情報通知へ同梱し、再生中は購読を解除するため継続的な解像度通知を追加しない。購読の変更と状態の世代で古い通知を除外する。別ウィンドウでは表示先のDocument・requestAnimationFrame・DPRを使う。

## VOICEVOX音声の生成と編集

字幕長はFill（次のキーまで）・Specified（指定長）・Match speech duration（音声長＋延長ms）の3モード。モードは発話の`subtitleDuration`に保存する。Match speech durationの延長量は設定画面で編集し、初期値0ms。音声長は注入された生成済み一覧から参照し、未生成では次のキーまで仮表示する。再生中・書き出し中はその処理が固定した音声一覧をレンダラーも使う。

字幕長をFillからSpecifiedへ切り替えると、その発話に一致する生成音声の長さを整数msに切り上げて初期値として保存する。未生成なら現在のFillの表示区間を使う。生成完了や再生成による指定長の更新は行わない。

発話ごとの字幕長は詳細のSubtitle durationで3モードを切り替える。新規キーはFill。Specifiedへの切り替え時は生成済み音声長を採用し、未生成なら現在の表示区間、表示区間がない場合は次のキーまでまたは標準5秒とする。Specifiedの0msは字幕だけ非表示。音声の生成要求には含めず、コピー＆ペースト・移動・Undo/Redoでは設定を維持する。

Speechレーンは字幕帯と生成済み音声の細い帯を上下に表示する。字幕帯をクリックして発話を選択し、指定終端が見える場合だけ右端ハンドルで長さを変更する。Fill・Match speech duration・クリップや次のキーによる切断箇所にはハンドルを出さない。タイムライン操作でモードを切り替えず、伸縮は一回のUndoへまとめる。既存のスナップ設定を適用し、生成音声の終端も候補にする。

Electron版のTimelineの追加メニューからVOICEVOXレイヤーを作成する。外部エンジンを起動し、レイヤー設定のEngine URL（初期値はhttp://127.0.0.1:50021）でConnectを実行すると、発話キーの個別編集欄で声・スタイルを選択できる。エンジンはGlitch Studioから起動・終了しない。

Speechレーンのダブルクリック、またはAdd speech key at playheadでキーを追加する。発話キーを一つ選択すると、専用の個別編集欄でVoice / style・本文・任意の読み・開始時刻を編集できる。ダブルクリックした時刻に既存のキーがあれば、そのキーを選択する。Ctrl/Cmdクリックまたは範囲選択で複数選択でき、通常キーと混在した移動・削除・コピー＆ペーストも一回のUndo/Redoで扱う。ドラッグは現在のスナップ設定（目盛り・クリップ境界・他のキー・シークバー）を使い、全選択に共通の移動量を適用する。通常キー・発話キーとも、同じレーンの未選択キーとの間に100msを残し、追い越しを防ぐ。開始時から100ms未満なら元の間隔を下限にする。時刻の数値入力も同じ制限を使う。Prev Keyframe / Next Keyframeは発話を含み、移動先の同時刻のキーをまとめて選択する。発話を含む選択は時間伸縮せず共通移動する。話速はレイヤー単位、声のスタイルIDは発話ごとの静的な設定。新しい発話は追加地点の直前の発話から声を引き継ぎ、直前がなければ最初の発話、空レイヤーならスタイルID 1を使う。保存順や現在の選択には依存せず、空文字キーも継承元に含む。追加後は独立した値として保持し、継承元の編集や移動には追従しない。複製ではコピー元の声を保持する。字幕装飾は専用の`GsTimeline.VoicevoxSubtitleSettings.vue`と`voicevoxSubtitle`対象で編集する。TextレイヤーのUI・定義・初期値・検証・生成処理は参照しない。音量・合成設定には既存のパラメータ編集を使う。Fit last clip to speechは生成済み音声に最後のクリップ終端を合わせ、キーを動かさない。

`VoicevoxGeneration`は編集後に要求を集約し、同じ要求を共有して直列に合成する。編集・削除で不要になった未着手の自動生成は待ち行列から取り除き、実行直前にも必要性を確認する。実行中の合成と手動再生成は完了させる。書き出しはスナップショット内の全要求を準備開始時から予約し、他の書き出しが使う要求は保持する。取消し・完了で最後の予約が外れた未着手要求は、現在の編集状態でも不要なら取り除く。要求キーは読み・スタイルID・話速だけから作り、キー移動・字幕装飾・再生音量の変更では再合成しない。Regenerateではエンジンの現在の辞書で読みを再解析する。古い要求の結果は異なる本文には採用せず、プロジェクト変更を跨ぐ結果は破棄する。

プロジェクトは現在の発話が参照する生成音声だけを`generatedSpeech`にAssetとは別に保持し、WAV・AudioQuery・エンジンバージョンを保存する。無効レイヤーやクリップ外の発話も参照に含め、削除済み・編集中の旧本文の結果は保存しない。未生成のキーも保存でき、Web版やエンジンが停止した環境でも保存済み音声を再生できる。`ProjectAudioReader`は素材と生成音声の所在を解決し、既存の音声subsystemへデコードを委ねる。

参照から外れた音声は`VoicevoxGeneration`が所有する`GeneratedSpeechCache`へ移す。Undo用の一時LRUで、WAVとJSON化したメタデータの合計128MiB・256件を上限にし、プロジェクト変更で破棄する。Undoで必要になった結果を保存状態へ戻してから旧結果を格納する。上限で失われた音声はElectron版では再生成し、Web版では未生成として扱う。保存・バックアップはスナップショット取得とエンコードでも現行参照へ絞り込む。

書き出しは準備開始時から全要求と利用可能な結果を予約し、準備後は返された音声一覧と開始時点の生成済み音声をスナップショットが所有する。動画では描画対象の子Sceneも内容時刻でたどり、各Sceneの波形・スペクトラムが参照し得る過去の発話を準備する。親のトリムで再生されない発話も描画用の履歴に含め、音声出力の計画から外れたことを理由に生成済み音声を捨てない。編集中の削除・一時LRUからの除去・同じ本文の再生成で書き出しの音声を失ったり差し替えたりしない。書き出し用の保持はUndo用キャッシュの容量制限から独立し、書き出し側の寿命で解放する。

プレビューでは再生開始時の生成音声一覧を固定し、シーク・ループ・通常音量編集でもその一覧を維持する。生成完了は再生を止めず、停止後の次回再生で採用する。未生成の発話は無音だが字幕を表示する。発話キー・声・クリップ・有効状態の編集とUndo/Redoは再生を停止する。動画書き出しは独立した編集状態のスナップショットを取り、必要な音声を準備してから開始する。失敗した発話を無音のまま書き出さず、取消しは生成待ちからも復帰できる。ダイアログの音声有無・サイズ概算は実行時の準備完了検証と分離し、未生成の発話も音声ありとして表示する。生成済みの場合は実際の音声長で選択範囲への交差を判定する。

UIの`timeline-keyframe-lanes.ts`が選択・スナップ・移動に必要な位置情報だけを公開する。`utterance`対象はUI側だけで扱い、パラメータBindingやTextレイヤーの定義には追加しない。コピーは本文・読み・声のスタイルIDを保持し、同じScene・レイヤーへシーク位置を先頭にして新しいIDで貼り付ける。発話または通常キーの一つでも衝突する場合は全体を貼り付けない。キー削除もルートBindingを独立した案として編集し、未設定のVisual Module引数や配列・構造体内のキーを削除した場合は、Undoで元の未設定状態へ戻す。

## 描画の検証と停止

`ProjectRenderValidation`は編集通知を同期的に受け、ノード・レイヤー・接続グラフ単位の診断を保持する。通常のliteral値と式本文は静的な形に含めず、構造・参照が変わった単位だけを検証する。接続の循環検査は辺の構成が変わったときだけ行う。

Scene追加・階層編集Commandは、操作条件とUndoに必要なIDの一意性を確認して状態を適用する。全Sceneの描画設定を適用前に再検証せず、変更通知を受けた`ProjectRenderValidation`が静的診断を更新する。別Sceneに静的エラーが残っていても編集を続けられる。

`PreviewRenderEngine`は静的診断が一つでもある場合、または実行時失敗を受けた場合に両プレビューのエンジンを破棄する。設定変更か明示的な再試行で静的エラーがなければ、最新のスナップショットから生成する。エラー中の差分をWorkerへ送ったり、復旧時に再送したりしない。静的診断と実行時失敗は別に保持し、古いWorkerの通知で解除しない。

Controllerは失敗を通知し、破棄の調整は`PreviewRenderEngine`に集約する。`RendererProjectSynchronizer`は差分の送信と成功・失敗の通知だけを担当し、失敗後の全量同期を行わない。静的診断の解除とプレビュー固有設定の変更では再試行を予約し、同じターンの通知をまとめる。Inline Visual Moduleの公開定義変更時は所有レイヤーの引数も再検証する。

Controllerの初回起動と破棄後の再生成は`relaunchManager()`を使い、保持した最新設定と新しいCanvasから生成する。レンダラーの`renderError`は失敗のみを通知し、Controllerのエラー表示は新しいManagerの初期化完了で解除する。Timelineの状態ストアは描画失敗を保持せず、Managerの破棄時に全状態を解除する。

書き出しは編集時の検証結果を使用し、開始時のプロジェクト全体の再検証は行わない。書き出し専用の出力設定と、実素材・GPU・エンコーダーの検証は別途行う。

## 最近のプロジェクトと別名保存

プロジェクトを開くファイル選択ダイアログは、最後に選択したファイルのディレクトリを次回の開始位置として記憶する。Web版は専用のピッカーIDでブラウザに記憶させ、保存先のフォルダ選択とは分離する。Electron版はmainがuserData内の`project-open-directory`へパスを保存し、再起動後や別の編集ウィンドウでも使用する。キャンセルでは記録を更新せず、記録の読み書きに失敗してもファイル選択・読み込みは続行する。

`recent-projects.ts`の`RecentProjectsController`がファイルの利用履歴を管理する。プロジェクトの読み込み成功と手動保存成功で更新し、最終利用日時順に最大20件を表示する。日時表示は`GsTime`を使う。未保存プロジェクト・再オープン可能な参照のないFile・自動バックアップは登録しない。履歴の削除は実ファイルを変更しない。

Web版はIndexedDBに`FileSystemFileHandle`を保存し、`isSameEntry()`で同一ファイルを判定する。一覧取得時にハンドルを保持し、クリック直後に読み取り権限を要求してから既存の`openProject()`へ渡す。Electron版はmainの`recent-projects.mjs`がuserData内にファイルパスと表示情報を保存する。ファイルごとの履歴を個別に置換し、他の作品を古い一覧で上書きしない。更新を全編集画面へ通知し、rendererには実パスを返さず、再オープン時に履歴IDからそのウィンドウ専用のファイル参照を再発行する。どちらも履歴の永続化失敗を本体のOpen/Saveの失敗にしない。

Save asは保存データに新しいプロジェクトIDを発行し、本体の書き込み成功後だけ`ProjectContext`へ反映する。キャンセル・失敗では元のIDを維持し、Undo/Redoの内容は保持する。待機中の通常Saveは、内容には要求時のスナップショットを使い、保存先とIDには先行するSave asの成功結果を使う。

`ProjectSaveController.isProjectSaving`は受付済みの手動保存を数え、待機・権限確認・エンコード・保存先選択・バックアップ・本体書き込み・バックアップ整理が終わるまでtrueになる。失敗・キャンセル・プロジェクト読込による要求の失効でも解除し、失敗ダイアログの確認待ちと自動バックアップ単独の実行は含めない。`App.vue`のヘッダーに保存中のメッセージを表示し、`project-close-guard.ts`が`beforeunload`で終了を保護する。保存中・エクスポート中はElectron版で終了を取り消して再操作を案内するダイアログを表示し、完了後も自動では閉じない。Web版は保存中・エクスポート中にブラウザー標準の終了確認を表示するが、文言の変更や終了の強制禁止はできない。

Electron版では保存中・エクスポート中でない場合に`hasUnsavedChanges`を終了要求時に評価し、未保存ならVueの`ui.confirm()`で「保存せずに閉じる／キャンセル」を確認する。キャンセルへ初期フォーカスを置き、保存済みのプロジェクトは確認せず閉じる。新規プロジェクトは初回保存まで未保存として扱う。`beforeunload`では一旦終了を取り消し、mainの`will-prevent-unload`後の通知からダイアログを開く。確認結果を非同期IPCで返し、元のウィンドウ終了・アプリ終了・再読み込みだけを一度再開する。連続した要求はmainで一つにまとめ、保存中・エクスポート中・画面破棄後の返答では再開しない。保存中・エクスポート中の終了防止を未保存変更の確認より優先する。

## Electronの更新UI

`desktop-update-ui.ts`がアプリ全体で共有する`desktopUpdateUi`を生成し、`main.ts`がルートUIのマウント後に初期化します。画面のマウント・アンマウントでは購読や更新UIを開始・破棄しません。Web版ではサービスを生成しません。

`DesktopUpdates`がmainから更新状態を取得・購読し、更新前の保存・プレビュー停止と失敗時の復帰を調整します。状態のrevisionを比較し、遅れて返った初期snapshotで新しい通知を巻き戻しません。`DesktopUpdateUiController`が確認・進捗ダイアログと再試行を管理し、複数の通知から操作しても確認や進捗ダイアログを重複表示しません。`App.vue`は共有状態を参照し、ヘッダとHelpメニューの操作をサービスへ渡します。

`GsDashboardDialog`も`desktopUpdateUi`を直接参照し、Electron版で更新が見つかると対象バージョンと通知ボタンを表示します。選択時はサービスの`requestUpdate()`を呼び、確認をキャンセルしてもDashboardを残します。App.vueによる状態・操作の中継はなく、Dashboard自身は追加の更新確認やIPC購読を行いません。

`GsDesktopUpdateDialog`が処理中の操作を抑止し、失敗後に閉じる・再試行を表示します。インストーラーの起動を試みた後の失敗は`restart-required`として扱い、再試行を隠してアプリの再起動を案内します。保存とプレビューはこの場合も復帰します。

`GsModal`は通常のclose時とアンマウント前にフォーカス制御を解除します。popupを直接破棄して別の確認へ移る場合にも背景の`inert`を残さず、破棄時には新しいモーダルのフォーカスを移動しません。

`ApplicationActivity`は読込・素材取込・書き出しとアプリ更新の受付を調整します。TimelineとVisual Moduleの書き出しは`acquireExport()`で受け付け、最後の書き出しが完了するまで読み取り専用の`isExporting`をtrueに保ち、終了ガードへ渡します。`ProjectSaveController.pauseForUpdate()`は新規保存とバックアップを止め、保存先予約の解放を含む受付済みの保存キューの完了を待ちます。`AppContext.pauseForDesktopUpdate()`がその後にプレビューを停止し、失敗時には保存とプレビューを復帰させます。通常の終了では各画面の終了ガードが保存・書き出し中の終了を拒否し、未保存変更の破棄を確認します。全体終了でも同意した画面から個別に閉じ、別画面の取消で閉じた画面を戻しません。更新準備はProjectやUndo/Redoの状態に含めません。配布とリリース手順は[desktopのREADME](../desktop/README.md)を参照してください。
