# Audio Renderer

音声ファイルのデコード、リサンプリング、PCMキャッシュ、取得元に依存しない音声解析を担当します。DOM・GPU・再生時計や、Asset・Player・Timelineの定義には依存しません。

`openAudioFile()`はBlobから音声トラックを開き、mono/stereoの対応と有限・正数の素材長を確認します。戻り値の`AudioFile`は、秒単位の`durationSeconds`・`sampleRate`・`readBlocks()`・`dispose()`だけを公開し、デコーダーの具体型を外へ渡しません。失敗時は資源を解放し、成功時の所有権は呼び出し側へ渡します。

`readBlocks()`は指定区間にかかるデコード済みのステレオPCMブロックを時刻順に返します。元のデコード境界により区間外のサンプルも含み得ます。モノラルは左右へ複製し、返したPCMの所有権は呼び出し側へ渡します。デコーダーのサンプルはPCMを返す前に解放するため、呼び出し側でcloseする必要はありません。

`AudioFileReader`は、呼び出し側が与える不透明なソースIDとopen関数を使います。IDからファイルを探す方法や表示名を知りません。開いた資源はreaderが所有し、disposeでまとめて解放します。読み取りは呼び出し側で直列化してください。

デコード済みPCMは全ソース合計の容量上限付きLRUキャッシュで保持します。リサンプリングに必要な前後のサンプルも読み、出力レートごとに窓を分けます。read()は指定レート・フレーム数の左右PCMを返し、素材外は無音にします。

`read()`は任意の`AbortSignal`を受け取り、open後・デコードブロック間・窓間で中断を確認します。待機中のデコーダー操作は完了させてから反復を閉じます。途中までのPCMを完全な窓としてキャッシュしません。中断前に開いたファイルもreaderが所有し、通常どおり`dispose()`で解放します。

`PcmResampler`は素材時刻から位相を決めます。前回の呼び出しの状態を使わず、先読み・シーク・書き出しで異なる区切りから読んでも同じ音声を生成します。

`AudioInputSpectrum`は`AudioInput`のサンプル位置から必要なPCM窓を計画し、読み出し済みPCMをFFTサイズの1/4間隔で解析します。`plan()`は必要な読み出し範囲だけを返し、読み出しを待つ処理やキャンセルは呼び出し側が所有します。`update()`で描画に採用した要求だけを反映し、同じ要求を二重に反映しません。指数平滑化は線形振幅に適用し、係数は音声のhop秒数と指定された時定数で決めます。

初回・取得元変更・逆方向シーク・窓関数/チャンネル変更では現在位置以下の最新のサンプル格子から1窓だけ解析し、平滑化の値は保持します。通常の前進では前回からの区間を解析し、追いつきは最大128区間、保持範囲を失った入力では残っているPCMに限定します。FFTサイズ（インスタンス変更）またはサンプルレートが変わると周波数binが変わるため平滑化を初期化します。過去の描画順や区間省略に依存する解析であり、シーク後の履歴再現は行いません。

FFTの数値計算と窓の振幅補正は共通の`WindowedFft`を使います。PlayerプレビューとSpectrogramが使う従来の`AudioSpectrum`も同じ計算を使いますが、履歴の進め方とリセット方針はそれぞれが所有します。
