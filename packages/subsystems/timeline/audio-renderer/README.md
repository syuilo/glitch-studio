# Timeline Audio Renderer

Timelineのクリップを指定したサンプル区間のステレオPCMへミックスします。クリップの時刻変換、所属Sceneの時刻での音量・式・キーフレーム評価、各階層の音量の適用を担当します。

素材PCMの読み出しだけを呼び出し側が注入します。読み出し側は、素材時刻（秒）と出力レート・フレーム数・`AudioPcmReadOptions`の符号付き倍率と素材範囲から同数の左右PCMを返し、素材外を無音にします。素材長の妥当性はファイルを開く境界で検証し、ミックス処理には渡しません。Glitch Studioのプロジェクト・Asset一覧、デコーダー、DOM・GPU・再生時計は所有しません。プレビュー再生と書き出しは別のインスタンスで同じ処理を使えます。

`renderClips()`の任意の`AbortSignal`を素材読み出しへ渡し、クリップ間と読み出し完了後でも中断を確認します。読み出し側が即時中断できなくても、古い要求の残りの素材取得・ミックスを進めません。

Sceneの音声計画はtimeline/sharedのgetSceneAudioClipsで作成し、renderClipsへ渡します。無効レイヤーの除外とScene階層の時刻変換は計画作成側に集約します。レンダラーは各階層の音量を適用してFloat32のまま加算し、子Scene単位やレイヤー単位のクリッピング・正規化は行いません。

計画の`sourceTiming.loop`が有効な配置は、要求されたサンプル区間だけを周期境界で分割して素材を読み出します。周期の原点は親Sceneで切り詰めた表示開始とは独立し、音量の時計は折り返しません。周期を整数サンプル数へ丸めて累積せず、絶対時刻から境界を求めるため、44.1kHzなどでも周回による位相のずれを生じさせません。接続部の自動クロスフェードは行いません。

Workerの起動、先読み・Scene全体のループ再生、出力ファイルのタイムスタンプとエンコーダーへの受け渡しは呼び出し側の責務です。クリップ内のループは音声計画に従い、このレンダラーが処理します。

`createTimelineAudioInput`は音声計画と所属Scene時刻から、描画用の`AudioInput`を作ります。窓は現在時刻の直前の区間で、48kHzのサンプル格子へ変換します。クリップの内容時刻や再生履歴を参照せず、窓内で既に終了したクリップもミックスします。Scene先頭より前やクリップ外は無音です。各描画要求・モーションブラーのサブサンプルはそれぞれのScene時刻で入力を作ります。

描画用の窓はミックス済みPCMを`AudioWindow`で包み、追加のPCMコピーを行いません。ビューを返した後はその配列を変更・再利用しません。

生成音声も通常素材と同じ不透明な`sourceId`で読み出す。音声計画へ載せる前の準備完了確認・合成要求・音声の保存は呼び出し側の責務であり、このミキサーでは扱わない。

素材時刻の変換はtimeline/sharedの`media-timing.ts`を使います。音量はScene時刻に固定し、速度やループでは戻しません。再生・描画用解析・書き出しが同じ符号付きの素材時計を読み出し側へ渡します。
