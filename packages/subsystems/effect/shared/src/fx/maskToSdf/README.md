# Mask to SDF

スカラー場の閾値輪郭までの距離をJFA+1で近似し、内側が負・境界が0・外側が正のスカラー場を出力する。距離の単位はShape SDFと同じく描画領域の高さを1とする。0〜1へ正規化・クランプせず、色や透明度も付けない。

## 入力とパラメータ

- Inputはスカラーの定数またはノード出力。初期値は0。
- Thresholdは初期値0.5。入力値が閾値を上回る領域を内側とし、閾値と等しい画素は外側とする。Thresholdを0〜1へ制限せず、負の値や1を超える値も使用できる。
- Invertは初期値false。内外の判定を反転する。閾値と等しい画素も反転後は内側になる。画面外は反転せず、常に背景とする。
- Threshold・Invertは画面全体で共通の値で、式・automationなどで変更できる。ノードによる画素ごとの変更は受け付けない。

透明背景の画像・文字では`Decompose Color`のAlpha、白黒画像では`RGB to`のLuminanceを接続する。ノイズなどのスカラー場は直接接続できる。完全に不透明な画像のAlphaを使うと、全画素が内側になる。

## 解像度と画面端

通常の自動解像度はInputを基準とする。定数だけなら描画先の解像度を使い、明示的な解像度指定は通常のエフェクトと同様に優先される。接続のfit・wrap・filterで入力を計算解像度へ描画した後に距離を求める。内部縮小は行わない。

画面外を背景とし、端に接する内側領域は描画領域の端で閉じる。完全に内側の入力は描画領域の矩形までの負の距離、完全に外側の入力は全画素65504になる。65504はShape SDFと同じ有限の空形状の値で、実際の距離ではない。1×1の内側入力は-0.5になる。JFAの候補探索は画面内に限定し、入力のwrap設定によって反対側へ伝播させない。

距離の単位は縦横とも高さ基準なので、縦長・横長でも等方的な距離になる。ただし元画像から復元できる輪郭は画素密度・入力の補間に依存し、解像度を変えても同じ輪郭精度を保証するものではない。

## GPU処理と精度

1. 入力からThresholdを引いた差を保存する。閾値付近の内外を16bitへの事前丸めで失わないため、減算は保存前に行う。
2. 各画素の上下左右で内外が切り替わる位置を線形補間し、その画素中心に最も近い境界点を候補として保持する。画面端では端までの半画素を使う。
3. 画面の最大寸法に応じて歩幅を半減するJFAを実行し、最後に歩幅1の追加パスを実行する。同距離の候補はIDが小さいものを優先する。
4. 候補までの画素距離を計算解像度の高さで割り、内外に応じた符号を付ける。

候補のIDは`r32uint`の2枚を交互に使用し、元の画素位置と局所オフセットから境界点を復元する。大きな画素座標そのものを16bit floatに保存せず、4K以上でもIDを丸めない。整数IDは補間せず`textureLoad`で読む。閾値との差・出力は`r16float`/`r32float`、局所オフセットは`rg16float`/`rg32float`で、`enable32bitDataTextures`に従う。閾値との差は保存形式の有限な範囲で飽和し、非常に大きな値が飽和した場合には境界の補間位置も変わり得る。

JFAは近似距離変換であり、さらに境界を有限個の点で近似する誤差がある。全ての閾値交差点を保持するわけではなく、斜めの輪郭・角・細線・小さな穴の距離を厳密には保証しない。元のベクター形状の復元や、光線の安全な歩幅としての利用は保証しない。

履歴・時刻・乱数に直接依存せず、同じ入力とパラメータなら同じ結果になる。JFA処理はこのエフェクト内に置き、他のエフェクトを参照しない。

中間テクスチャは1画素あたり16bit設定で14バイト、32bit設定で20バイト。出力を含めるとそれぞれ16バイト・24バイトで、3840×2160では約127MiB・190MiBになる。JFAは4Kで13パス、入力準備・候補生成・最終出力を含めて16パスとなる。実際の処理時間はGPUと入力による。

`CHROME_PATH`を設定して`node --test packages/subsystems/effect/shared/test/mask-to-sdf.gpu.test.mjs`を実行すると、16bit/32bitの実描画を検証する。`GS_MASK_SDF_BENCHMARK=1`も設定すると、64×64のチェッカー入力を3840×2160へ拡大したマスクで計測する。初回を除く5回の平均で、CPUのコマンド生成からGPU完了までを含み、画素のCPU読み戻しは含まない。
