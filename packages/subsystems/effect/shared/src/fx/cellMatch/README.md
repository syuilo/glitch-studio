# Cell Match

主入力Inputを等サイズの長方形セルに分割し、配置先における副入力Referenceの平均色・平均輝度へ近づくように画像片を配置する。Placement Modeで一対一の並べ替えと再利用を選択できる。セル内の細部・RGBAは変更しない。Adaptive分割・セルの拡縮・回転・色補正は行わない。他エフェクトの実装には依存せず、既存の`_def_.ts`・`_impl_.ts`のglobで登録される。

## 格子と入力

FrequencyとSize Referenceでセルの幅・高さを指定する。両軸で同じ基準寸法を使い、解像度だけを変えても相対的な寸法を保つ。Phaseは中央原点・+Yが上の格子座標へ加算し、1で1セル周期となる。出力の自動解像度はInputだけから求める。両入力は同じ描画領域で、各接続のFit・Wrap・Filterに従って参照する。

画面と交差するセルは、一部が欠けていても本来の寸法で扱う。画面外の画像参照は描画領域の端でMirror Repeatしてから接続のFitを適用する。解析と描画で同じ規則を使い、セル自体の寸法や格子座標は折り返さない。反射部分が画面内へ移ったり、移動後の一部が画面外へ隠れたりするため、画面内の画素数・色分布の保存は保証しない。

## 類似度

Samples Per Cellは1〜256、既定値16。セルを指定数の等面積領域へ分け、各中心のpremultiplied RGBAを平均する。解析位置は解像度に依存せず、端セルの反射部分も等しい重みで含める。有限個のサンプルによる推定であり、細い模様やセル内構造の一致は保証しない。

代表RGBは平均premultiplied RGBを平均alphaで割って求める。完全透明ならRGBを0とし、0除算しない。色差は以下のように定義する。

- Average Color：代表RGB差の二乗を3成分で平均する。
- Average Luminance：代表RGB差と係数`(0.2126, 0.7152, 0.0722)`の内積の二乗を使う。

どちらも色差に`clamp(min(主入力の平均alpha, 副入力の平均alpha), 0, 1)`を掛け、平均alpha差の二乗を加える。透明部分を黒として比較せず、透明な配置先には透明な画像片が選ばれやすくする。RGBを0〜1へ制限せず、HDR入力も作業RGBのまま比較する。

Position Biasは、元位置から配置先への距離の二乗へ掛ける重み。距離は長辺全体=1の共通単位で測る。既定値0では色・透明度だけを評価し、大きくすると元の配置を優先する。

## 配置方式

Placement Modeは以下の2方式。既定値はOne-to-One。

- One-to-One：各画像片を一度ずつ使う。二つの割当の交換による近似探索を行う。
- Allow Reuse：配置先ごとに全ての主入力セルを比較し、上記の色・透明度・Position Biasを合わせた誤差が最小のセルを選ぶ。同じ画像片を何度でも使い、使われない画像片も生じる。

Allow Reuseでは同点なら元位置のセルを優先し、それ以外はセル番号が最小の候補を選ぶ。平均色が同じで細部だけが異なる画像片も、GPUの実行順に依存せず安定して選択する。同じ入力を両方につないだ場合は元画像を保つ。一様なReferenceでも、より近い画像片があれば繰り返し配置する。

再利用時は一つの配置先を64laneのworkgroupへ割り当て、候補を分担して全て比較した後に最小誤差の候補を集約する。他の配置先の割当には依存せず、一回のdispatchで全配置先を確定する。One-to-One Iterationsは使用しないため、0でも再利用の配置は行う。セル数Nに対して比較量はO(N²)となり、高密度の格子では負荷が増える。

主入力に存在しない色を作ることはできないが、再利用では不足している画像片を繰り返すことで副入力の色分布へ近づけられる。

## 一対一の探索

毎回元の配置から開始し、二つの配置先の参照元を交換したとき、両者の誤差の合計が厳密に減る場合だけ採用する。同点では交換しない。同じ画像を両入力へつないだ場合や、一様なReferenceに対して不要なシャッフルを起こさない。セルの重複・欠落はなく、全体最適の保証はない。主入力に存在しない色や不足している画像片を作ることはできない。

One-to-One Iterationsは0〜1024、既定値128。1回で互いに重ならないセル対を並列に比較する。0では元画像を返す。参加者数を2冪へ切り上げ、余りを交換しないダミーとして、総当たり戦の円環法でペアを作る。round番号のbit反転順で遠方の候補にも早く触れ、`参加者数-1`回で全セル対を一度ずつ比較する。探索回数を増やしても評価誤差は増加しないが、色差と移動距離のトレードオフや局所解は残る。

GPU上では各dispatchのセル対が重ならないため、割当bufferをその場で安全に交換できる。CPUへの読み戻し・描画履歴・時刻・フレーム番号には依存しない。動画では入力や格子の変化に応じてセルが瞬時に入れ替わり、時間方向の平滑化は行わない。

## GPUリソースと検証

統計は32byte/セル、割当は4byte/セル。一対一では各反復のuniformを別領域に保持し、dynamic offsetで選ぶ。解析・初期化・交換・描画の順に実行する。再利用では解析・全候補からの選択・描画の順に実行し、反復用のuniform領域は追加確保しない。格子の行列数や必要な反復容量が増えた場合はbufferを再作成し、入力の定数／テクスチャ構成ごとにpipelineを保持する。GPUのbuffer・dispatch上限を超える格子はエラーにし、解像度に応じてセル数や解析数を自動削減しない。

`CHROME_PATH`を指定して`node --test packages/subsystems/effect/shared/test/cell-match.gpu.test.mjs`を実行すると、実際のWebGPUで画像片の配置・一対一対応・再利用と同点処理・方式切替・反射・透明度・解像度独立性・再現性を検証する。
