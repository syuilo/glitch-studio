# Cell Match

主入力Inputを等サイズの長方形セルに分割し、配置先における副入力Referenceの平均色・平均輝度・セル内構造へ近づくように画像片を配置する。Placement Modeで一対一の並べ替えと再利用を選択できる。セル内の細部・RGBAは変更しない。Adaptive分割・セルの拡縮・回転・色補正は行わない。他エフェクトの実装には依存せず、既存の`_def_.ts`・`_impl_.ts`のglobで登録される。

## 格子と入力

FrequencyとSize Referenceでセルの幅・高さを指定する。両軸で同じ基準寸法を使い、解像度だけを変えても相対的な寸法を保つ。Phaseは中央原点・+Yが上の格子座標へ加算し、1で1セル周期となる。出力の自動解像度はInputだけから求める。両入力は同じ描画領域で、各接続のFit・Wrap・Filterに従って参照する。

画面と交差するセルは、一部が欠けていても本来の寸法で扱う。画面外の画像参照は描画領域の端でMirror Repeatしてから接続のFitを適用する。解析と描画で同じ規則を使い、セル自体の寸法や格子座標は折り返さない。反射部分が画面内へ移ったり、移動後の一部が画面外へ隠れたりするため、画面内の画素数・色分布の保存は保証しない。

## 類似度

Samples Per Cellは1〜256、既定値16。平均色・平均輝度ではセル全体を、構造比較では下記の各領域を解析する。領域内を解析点数に応じた等面積の区画へ分け、各中心のpremultiplied RGBAを平均する。解析位置は解像度に依存せず、端セルの反射部分も等しい重みで含める。有限個のサンプルによる推定であり、極端に細い線や高周波の模様を必ず検出できるわけではない。

代表RGBは平均premultiplied RGBを平均alphaで割って求める。完全透明ならRGBを0とし、0除算しない。色差は以下のように定義する。

- Average Color：代表RGB差の二乗を3成分で平均する。
- Average Luminance：代表RGB差と係数`(0.2126, 0.7152, 0.0722)`の内積の二乗を使う。
- Cell Structure：Structure Gridでセル内を2×2または4×4の等面積領域へ分け、同じ相対位置の領域同士をAverage Colorの基準で比較する。既定値は2×2。全体の平均色が同じでも、左右・上下の配色や透明部分の配置を区別する。Structure Gridは平均色・平均輝度の方式では使用しない。

各領域の色差に`clamp(min(主入力の平均alpha, 副入力の平均alpha), 0, 1)`を掛け、平均alpha差の二乗を加える。透明部分を黒として比較せず、透明な配置先には透明な画像片が選ばれやすくする。RGBを0〜1へ制限せず、HDR入力も作業RGBのまま比較する。

構造比較ではSamples Per Cellを領域へできるだけ均等に配り、割り切れない余りは上から下・左から右の順に1点ずつ加える。全領域を最低1点ずつ読むため、実際のセル全体の解析数は`max(Samples Per Cell, 領域数)`となる。例えば4×4・Samples Per Cell=1では16点、17では一領域が2点で他の15領域が各1点。解析数が異なっても、等面積の各領域の比較誤差には同じ重みを与える。

構造の誤差は領域数で割って平均し、Position Biasを一度だけ加える。Structure Gridを切り替えても、色・透明度の誤差に対する移動距離の相対的な重みを保つ。構造は比較用の特徴量であり、出力の画像片を2×2・4×4の平均色に塗りつぶす処理ではない。

Position Biasは、元位置から配置先への距離の二乗へ掛ける重み。距離は長辺全体=1の共通単位で測る。既定値0では色・透明度だけを評価し、大きくすると元の配置を優先する。

## 配置方式

Placement Modeは以下の2方式。既定値はOne-to-One。

- One-to-One：各画像片を一度ずつ使う。二つの割当の交換による近似探索を行う。
- Allow Reuse：配置先ごとに全ての主入力セルを比較し、上記の色・透明度・Position Biasを合わせた誤差が最小のセルを選ぶ。同じ画像片を何度でも使い、使われない画像片も生じる。

Allow Reuseでは同点なら元位置のセルを優先し、それ以外はセル番号が最小の候補を選ぶ。平均色が同じで細部だけが異なる画像片も、GPUの実行順に依存せず安定して選択する。同じ入力を両方につないだ場合は元画像を保つ。一様なReferenceでも、より近い画像片があれば繰り返し配置する。

再利用時は一つの配置先を64laneのworkgroupへ割り当て、候補を分担して全て比較した後に最小誤差の候補を集約する。他の配置先の割当には依存せず、一回のdispatchで全配置先を確定する。One-to-One Iterationsは使用しないため、0でも再利用の配置は行う。セル数N・比較領域数Kに対して比較量はO(N²K)となり、高密度の格子や細かい構造比較では負荷が増える。

主入力に存在しない色を作ることはできないが、再利用では不足している画像片を繰り返すことで副入力の色分布へ近づけられる。

## 一対一の探索

毎回元の配置から開始し、二つの配置先の参照元を交換したとき、両者の誤差の合計が厳密に減る場合だけ採用する。同点では交換しない。同じ画像を両入力へつないだ場合や、一様なReferenceに対して不要なシャッフルを起こさない。セルの重複・欠落はなく、全体最適の保証はない。主入力に存在しない色や不足している画像片を作ることはできない。

One-to-One Iterationsは0〜1024、既定値128。1回で互いに重ならないセル対を並列に比較する。0では元画像を返す。参加者数を2冪へ切り上げ、余りを交換しないダミーとして、総当たり戦の円環法でペアを作る。round番号のbit反転順で遠方の候補にも早く触れ、`参加者数-1`回で全セル対を一度ずつ比較する。探索回数を増やしても評価誤差は増加しないが、色差と移動距離のトレードオフや局所解は残る。

GPU上では各dispatchのセル対が重ならないため、割当bufferをその場で安全に交換できる。CPUへの読み戻し・描画履歴・時刻・フレーム番号には依存しない。動画では入力や格子の変化に応じてセルが瞬時に入れ替わり、時間方向の平滑化は行わない。

## GPUリソースと検証

統計は一領域あたり32byteで、平均色・平均輝度は32byte/セル、2×2の構造比較は128byte/セル、4×4は512byte/セル。割当は全方式で4byte/セル。平均色・平均輝度では構造用の追加領域を確保しない。格子の行列数・比較領域数・必要な反復容量に応じてbufferを再作成し、入力の定数／テクスチャ構成ごとにpipelineを保持する。GPUのbuffer・dispatch上限を超える格子は、構造の領域数を含めてエラーにし、解像度に応じてセル数や解析数を自動削減しない。

一対一では各反復のuniformを別領域に保持し、dynamic offsetで選ぶ。解析・初期化・交換・描画の順に実行する。再利用では解析・全候補からの選択・描画の順に実行し、反復用のuniform領域は追加確保しない。

`CHROME_PATH`を指定して`node --test packages/subsystems/effect/shared/test/cell-match.gpu.test.mjs`を実行すると、実際のWebGPUで画像片の配置・一対一対応・再利用と同点処理・方式切替・反射・透明度・解像度独立性・再現性を検証する。構造比較では全体平均が同じな縦横模様・2×2の平均まで同じな反転チェッカー・透明度の配置・解析予算・Position Biasの正規化・領域数を含むGPU容量制限を確認する。
