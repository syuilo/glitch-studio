# Raster desync

入力を左上から右下へ並ぶラスタの画素列として解釈し、読み進める行幅の誤り、読み取り開始位置のずれ、途中の誤りと再同期を模す。画像の加工エフェクトとして、Visual Moduleとタイムラインのエフェクトレイヤーの両方で使える。登録は既存の`_def_.ts`・`_impl_.ts`のglobで行う。

## 責務

- `_def_.ts`：入出力と設定項目。
- `raster.ts`：仮想ラスタの走査と、行ごとの参照位置の作成。入力の画素やGPUを参照しない。
- `_impl_.ts`：出力の縦横比からの仮想寸法の決定、行状態の更新・転送、入力pipelineとGPUリソースの管理。
- `shader.wgsl`：行状態から入力座標を計算し、元の解像度の画像を直接読み取る。

## ラスタの走査

`rasterDensity`はSize Referenceの基準寸法に対する仮想画素数。既定値はLong Side。縦横比から各軸の寸法を求め、行幅が整数になるよう最後に丸める。画像を仮想解像度へ縮小する処理は行わず、行内の小数座標も維持する。出力解像度だけが変わっても、ラスタの段差や破損位置は同じになる。

正しい行幅をW、出力の行・列をy・x、蓄積したずれをphaseとすると、基本の読み取りアドレスは`y * W + x + phase`。次の行へ進むたびに`W * rowWidthError / 100`をphaseへ加え、間違った幅で読み進める挙動にする。正の値では画素列の先へ、負の値では手前へずれる。画像の列境界をまたいだ分は、前後の行へ繰り越す。

`startPosition`は上からの割合で、該当する仮想行から処理を開始する。開始前の行はそのまま返す。`readOffset`はWに対する百分率の初期位相で、開始時だけ適用する。

ランダムな同期ずれは各行に最大1回発生する。行の途中にある発生位置から位相を正負に変更し、そのずれは次の行にも引き継ぐ。行状態には発生前後それぞれの行番号・列オフセットと、発生する列位置を保存する。確率・位置・振幅には用途を分けた乱数を使い、Seedと絶対行番号だけで決める。

再同期が有効なら、開始行から指定した行数ごとにphaseをゼロへ戻す。初期オフセットを再注入する処理は行わない。再同期した行でも新たな誤りは発生し、行幅の誤りも次の行から蓄積する。無効なら画像末尾まで位相を引き継ぐ。

## 精度と入力の扱い

CPU側でf64の位相を計算し、GPUへ渡す前に整数の行番号と0以上W未満の列オフセットへ分解する。GPUで巨大な一次元アドレスを計算すると行の下側ほど小数精度が失われるため、この形式で元画像の細部を保つ。行状態は1行につき5個のf32で、GPUへは設定が変わったときだけ転送する。入力画像の更新だけでは走査をやり直さない。

参照先が画像の最初・最後の行を越える場合は、通常の生成参照関数に渡し、入力接続のFit・Wrap・Filterに従う。画素列としての列の折り返しと、画像全体に対する入力接続のwrapは別の処理である。

RGBAをまとめて移動し、Amountでの合成もpremultiplied alphaのまま行う。元位置の透明度を固定する処理や、追加のpremultiplyは行わない。定数入力も通常のShaderInputとして扱う。

前フレームの履歴・描画回数・フレームレートを使わない。動きを付ける場合はSeed、読み取りオフセット、行幅などへ式やオートメーションを設定する。仮想寸法や行状態のバッファがGPU・数値精度の上限を超える設定は描画エラーとし、黙って密度を下げることはしない。
