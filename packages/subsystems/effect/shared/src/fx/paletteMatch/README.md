# Palette Match

主入力Inputの画素位置とalphaを保ち、Oklabの平均色・共分散を副入力Referenceへ近づける。参照の色調を移す統計方式であり、色分布全体の一致や有限色への減色は行わない。Amountは持たず、適用量の合成は後段のノードで行う。他エフェクトの実装には依存せず、既存の`_def_.ts`・`_impl_.ts`のglobで登録する。

## 入出力と設定

| 設定 | 既定値 | 動作 |
| --- | --- | --- |
| Input | 透明 | 加工する画像・色。自動解像度はこの入力だけから求める |
| Reference | 透明 | 参照する画像・色。解析できる画素がなければInputをそのまま返す |
| Lightness Match | 0 | OklabのLを近づける強さ。0では元のLを保持、1では転送結果のLを使用 |
| Chroma Match | 1 | Oklabのa・bを近づける強さ。0では元の色味を保持 |
| Maximum Gain | 4 | Oklabの共分散転送行列の主軸における最大増幅率。1〜16 |
| Analysis Samples | 4096 | 両入力を解析する点数。1〜65536 |
| Input Analysis Mask | 1 | 主入力の解析重み。scalarの定数・テクスチャに対応 |
| Reference Analysis Mask | 1 | 参照画像の解析重み。scalarの定数・テクスチャに対応 |

明度・色味の強さは0〜1へ制限する。範囲付きの数値設定は丸め・範囲制限して使用し、非有限値は既定値へ戻す。Lightness Matchはlinear RGBの輝度YではなくOklabのLを保持する設定。0を選ぶほど、明度も含めたReferenceとの統計の一致には制約が生じる。両方の強さが0なら解析と色空間変換を省略し、そのままInputを返す。

解析マスクは対象画素を選ぶためだけに使い、出力への適用量やalphaには掛けない。例えばInputの人物だけを解析しても、得られた色変換は画像全体へ適用する。出力を部分的に変える場合は後段で合成する。

## サンプリングと透明度

Analysis Samples個の等面積区画を作り、各中心を解析する。平方数以外の点数でも行ごとの区画数に応じた面積を割り当て、全点を同じ面積の代表として扱う。位置と個数は出力解像度・描画時刻・フレーム数に依存しない。両入力と解析マスクは出力画面を基準とした同じ位置で、接続ごとのFit・Wrap・Filterに従って参照する。Reference全体が常に解析されるわけではなく、Coverによる切り取りなども解析結果へ反映する。

premultiplied sRGBを未乗算RGBへ戻し、linear sRGBを経てOklabへ変換する。各点の重みは`clamp(alpha, 0, 1) × clamp(解析マスク, 0, 1)`。完全透明な点とマスク0の点を除外し、透明部分を黒として平均しない。非有限のalpha・マスク・変換後の色も解析から除外する。どちらかの入力で有効な重みがなくなったら、その描画ではInputをそのまま返し、以前の変換を使い回さない。

有限個のサンプルなので、細い図形や解析点の間にある模様を必ず含める保証はない。必要ならAnalysis Samplesを増やす。画像内容や出力解像度に合わせて解析数を自動変更しない。

## 平均と共分散の転送

GPUで重み付き平均と共分散を求める。差し引きによる桁落ちを避けるため、`E[xxᵀ] - E[x]E[x]ᵀ`ではなく重み付きの並列Welford法で偏差積を集約する。RGBを別々にスケールする方法ではなく、Oklabの色成分間の相関も含めた3×3の色変換を求める。

主入力の平均を`μs`、参照を`μr`、共分散を`Cs`・`Cr`とすると、転送後の色は`μr + A × (色 - μs)`。行列はGaussianの対称な転送を使う。

`A = Cs^(-1/2) × (Cs^(1/2) × Cr × Cs^(1/2))^(1/2) × Cs^(-1/2)`

行列の平方根は、3×3対称行列の巡回Jacobi法を固定10巡で固有値分解して求める。入力と参照の共分散へ同じ正則化を加え、特異な行列や微小な分散でも逆平方根を有限に保つ。HDRで行列積がoverflowしにくいよう、両共分散を共通の尺度で正規化してから計算する。

得られた対称行列の固有値を0〜Maximum Gainへ制限する。これはOklabの平均からの偏差の増幅上限であり、平均色の移動量やRGB出力値の上限ではない。参照の変動が大きくても、ノイズを無制限に拡大しない。正則化・増幅上限・独立した明度と色味の調整により、参照の共分散を厳密には再現しない場合がある。

主入力の共分散のtraceが`1e-8`以下なら、行列を恒等にして平均色だけを移動する。単色入力に参照の模様を生成せず、解析1点の場合にも画像の細部を消さない。主入力に変動があり、参照のtraceが同じ閾値以下なら、転送結果は参照の平均色になる。平均・共分散が同一なら変換自体を省略し、自分自身を参照した画像を色空間変換の往復で変えない。

## 色と出力

転送前後のOklabのLをLightness Match、a・bをChroma Matchでそれぞれ補間してからsRGBへ戻す。主入力のalphaを一度だけ乗算し、位置や被覆率は変えない。符号付きのsRGB変換・立方根を使い、RGBを0〜1へclampせずHDR・負値を保持する。f32の色空間変換で有限範囲を超える画素は元の値を保持する。最終的な保存範囲・精度はINTERMEDIATE_TEXTURE_FORMATに従う。

同じ色には同じ変換を適用し、被写体の意味や画像間の空間的な対応は解析しない。例えばReferenceに空の青が多いと人物へも青みが移り得る。解析マスクで対象の色を絞り込める。動画もその描画の入力から毎回解析し、履歴による時間方向の平滑化や変換の固定は行わない。

## GPU処理と検証

- `analyze.wgsl`：1workgroupあたり64点を解析し、部分統計へ集約する。
- `transform.wgsl`・`matrix.wgsl`：1workgroupで部分統計を最終集約し、色変換を計算する。
- `shader.wgsl`・`color.wgsl`：主入力へ変換を適用する。出力画像を解析解像度へ縮小しない。
- `_impl_.ts`：定数／テクスチャの入力構成ごとのpipelineとGPUリソースを所有する。

統計は常にf32のstorage buffer。入力・参照の部分統計は一組96byteで、最大65536点では1024組・96KiB。色変換は96byte。解析点数の増加で必要な容量が増えた場合だけbufferを再作成する。解析・色変換計算・出力描画の順に実行し、CPUへの読み戻しは行わない。GPUのbuffer・dispatch上限を超える場合はエラーにする。

`CHROME_PATH`を設定して`node --test packages/subsystems/effect/shared/test/palette-match.gpu.test.mjs`を実行すると、既知の対称な色変換・全共分散成分・独立調整・主軸の増幅上限・alpha重み・解析マスク・空の統計・解析容量変更・Fit・解像度独立性・HDRと負値・データ精度に依存しないrgba16floatの画像出力を実際のWebGPUで確認する。

計算の参考：[Oklabの原典](https://bottosson.github.io/posts/oklab/)、[Gaussianの対称転送行列](https://djalil.chafai.net/blog/2010/04/30/wasserstein-distance-between-two-gaussians/)。
