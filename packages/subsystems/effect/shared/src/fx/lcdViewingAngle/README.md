# LCD Viewing Angle

入力画像をTN型液晶へ表示したときの、視線方向による色・コントラスト・階調の変化を計算する。液晶セルを48層へ分割し、各層の複屈折による偏光伝搬を380〜780nm・5nm刻みの81波長で積分する。経験的なガンマカーブや色相回転で変化を作るエフェクトではない。

既存のLCDはRGBサブピクセルの模様を作り、このエフェクトはサブピクセルを構成する各原色の光学応答を扱う。必要ならLCD Viewing Angleの後へLCDを接続する。画像の投影・台形変形・モアレ・残像は扱わない。

## パラメータ

| パラメータ | 初期値 | 意味 |
| --- | --- | --- |
| Input | 透明 | 液晶へ表示するsRGB画像 |
| Horizontal Viewing Angle | 0 | 正面の法線からの水平角。正で観察者が右側、負で左側 |
| Vertical Viewing Angle | 0 | 正面の法線からの垂直角。正で観察者が上側、負で下側 |
| Amount | 1 | 未加工画像とのlinear RGBでの混合量。0〜1へ制限 |
| Cell Thickness | 5 µm | 液晶セルの厚み。負値は0 |
| Ordinary IOR / Extraordinary IOR | 1.5 / 1.6 | 常光・異常光の屈折率。それぞれ1以上へ制限 |
| Twist Angle | 0.25 turn（90°） | 背面から前面への配向軸の時計回りのねじれ。符号でねじれ方向を変更。±1 turnへ制限 |
| Pretilt Angle | 2° | 駆動前と両界面での、画面に対する配向軸の傾き。±45°へ制限 |
| Panel Rotation | 0 | 液晶の配向と2枚の偏光板を一緒に時計回りへ回転する。画像自体は回転しない |
| Polarizer Angle | 0 | Panel Rotationに対する背面の偏光板の向き |
| Analyzer Angle | 0.25 turn（90°） | Panel Rotationに対する前面の偏光板の向き |
| Calibrate Front View | 有効 | 正面応答からRGBごとの駆動値を逆算し、正面の黒・白・階調を入力画像へ合わせる |
| Brightness | 2 | linear RGBでの光量倍率。初期値2は最初の偏光板による1/2の損失を補う。負値は0 |

角度は共通のangle入力と同じturn単位で指定する。水平・垂直角はそれぞれXZ・YZ面での法線からの角度であり、1周を同じ方向へ戻した後、前面の±85°へ制限する。2軸の角度を同時に指定した場合も、外側での光の方向を正規化してから屈折を計算する。

InputとAmountは定数・ノード接続に対応する。他の設定は画面全体に共通する光学系のパラメータで、式・automationによる変化には対応するが、画素ごとの場の接続には対応しない。物理量を画面の解像度・縦横比・Size Referenceで換算しない。

## 光学モデル

等エネルギーの無偏光バックライト → 理想線偏光板 → ねじれた一軸性液晶 → 理想線偏光板 → RGBカラーフィルターを計算する。波長によって位相差を変え、透過光を各原色の帯域内で合算する。

セル内の正規化深度を`z`、駆動値を`u`（0〜1）、Pretilt Angleを`α₀`とすると、画面からの傾斜を`α(z) = α₀ + (π/2 - α₀) u sin(πz)`とする。界面の配向は保ち、中央ほど法線方向へ立ち上がる。面内の配向は深度に対して一様にねじる。これは与えられた分子配向から光を計算するモデルであり、電圧・弾性定数から配向を解くものではない。

外側を空気とし、接線方向の波数を各層で保存する。常光の法線方向波数は`qoz = sqrt(no² - qx² - qy²)`。異常光は一軸性媒質の分散関係`|q|²/ne² + (1/no² - 1/ne²) (q・director)² = 1`を法線方向の波数について解き、前進する根を採用する。各層の厚みを`Δd`とすると、固有偏光間の位相差は`2π Δd (qez - qoz) / λ`になる。

偏光の基底には常光の屈折方向を使う。配向軸・偏光板の軸をその横断面へ射影し、各層を損失のないJones行列として順に通す。異常光の固有偏光もこの共通横断面で近似するため、界面の電磁場を厳密に接続するBerreman法ではない。初めの偏光板の1/2の光量損失を含み、各層は光量を増やさない。

RGBカラーフィルターは中心610 / 545 / 460nm、標準偏差25 / 22 / 20nmのGaussian透過帯域とし、台形則で積分する。各原色のフィルター面積・バックライト強度は正面の白で校正済みとし、帯域内での平均透過率をlinear RGBの各原色強度として扱う。原色の色度はsRGBへ固定する。特定製品のバックライト・フィルターの実測分光分布や、帯域内での色度移動を再現するものではない。

## 正面校正と透明度

Calibrate Front Viewが有効な場合、各原色の正面応答から最小・最大透過率を求め、その間へ入力のlinear RGB値を対応させて駆動値を逆算する。正面応答が非単調な場合は、最暗状態から最明状態へ進んで最初に目標値へ到達する区間を使う。極端な材質設定で応答に複数の山がある場合、駆動値の解が切り替わることがある。

同じ駆動値で観察方向の透過率を計算し、正面の黒・白を基準に正規化する。Brightness=2の正面では入力の0〜1階調と一致し、斜めから見た黒浮き・減光・階調反転は残る。正面の明暗差が1e-6以下の場合は逆変換せず、実際の透過率へ戻す。校正後の相対透過率は0〜1へ制限する。

校正を無効にした場合は、入力のlinear RGB値を`u = 1 - input`として駆動へ直接対応させ、光学モデルの透過率へBrightnessを掛ける。Brightness=1でバックライトに対する透過光量を確認できる。

入力はpremultiplied sRGBとして読み、alphaが0なら透明色を返す。未乗算へ戻してlinear RGBへ変換し、光学応答の適用・Amountによる混合・sRGBへの変換後に、元のalphaを乗算する。光学的な暗さで被覆率を変えない。Amount=0は変換の往復を省略して入力をそのまま返す。校正で扱う画像のRGB範囲は0〜1とする。

## GPU上の処理と制約

駆動値256点の正面応答・観察方向の応答と、校正後の画像用応答表をGPU上にfloat32で保持する。これらは物理計算のキャッシュであり、手描き・実測のLUTではない。初回・材質変更時は4パス、視線だけの変更時は3パス、校正・Brightnessだけの変更時は2パス、入力画像・Amount・時刻だけの変更時は画像適用の1パスを実行する。画像用の応答表はlinear RGB値で線形補間する。

固定の分割・サンプリングを使うため、極端に厚いセル、大きい屈折率差、複雑な正面応答では精度が低下する。界面反射・多重反射・異常光のウォークオフ・屈折率の波長分散・補償フィルム・電圧からの配向解析・散乱・実機固有の構造は扱わない。画像内では平面の液晶を同じ方向から見る。視点距離による画面内の角度差は計算しない。

描画履歴・時刻・乱数に依存しない。キャッシュは現在の光学パラメータだけから再生成でき、出力形式は`intermediateTextureFormat`に従う。

## 使用例

- 正面の初期値からVertical Viewing Angleを±30〜60°へ動かすと、見る方向によって異なる暗部・色・階調の変化を確認できる。
- Panel Rotationを90°回すと、視野角特性も画面内で回転する。Horizontal Viewing Angleとの組み合わせにも使える。
- Calibrate Front Viewを無効、Brightnessを1へ設定すると、偏光板やセル厚みによる透過光量そのものを観察できる。
