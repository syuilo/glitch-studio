# LCD Viewing Angle

液晶画面を斜めから見たときの色・階調の変化、階調反転、コントラスト低下を数式で近似する画像エフェクト。TN液晶風の方向依存性を持つ作画用のモデルで、特定の実機の測定値や、液晶分子・偏光板の光学シミュレーションには基づかない。

既存のLCDエフェクトがRGBサブピクセルの模様を担当し、このエフェクトが視線方向による色の応答を担当する。必要に応じてVisual Moduleやタイムラインで組み合わせる。画像の形や参照位置は変えない。

## パラメータ

| パラメータ | 初期値 | 意味 |
| --- | --- | --- |
| Input | 透明 | 加工する色・画像 |
| Horizontal Viewing Angle | 0.125 turn（45°） | 正面から右側への視線角度。負は左側 |
| Vertical Viewing Angle | 0 turn | 正面から下側への視線角度。負は上側。左右より強く階調が変化する |
| Color Shift | 0.5 | RGB間の階調応答の差。0では灰色を無彩色のまま変換する |
| Contrast Loss | 0.5 | 視線角度に応じた漏れ光と白の減光の強さ |
| Inversion | 1 | 詳細設定。階調カーブの折り返しを使う強さ。0では明暗の順序を保つ |
| Amount | 1 | 入力と変換結果の混合量 |

Input・Horizontal Viewing Angle・Vertical Viewing Angle・Amountはノード接続に対応する。全パラメータで式・オートメーションを利用できる。角度は既存のangle入力と同じturn単位で、1が360°。正面は両角度が0。両角度をそれぞれ±85°へ制限し、背面や複数周への回転としては扱わない。他の設定は0〜1に制限する。

角度へスカラー場を接続すると、画素ごとに異なる視線を表現できる。一定角度では全画素に同じ応答を適用する。画面上の位置や仮想的な観察距離から視線を自動計算する機能は持たない。

## 階調応答

水平・垂直角度の正弦を`h, v`とし、方向による応答を`0.55h|h| + v|v|`で近似する。符号付きの二乗で正面付近の変化を滑らかにし、左右より上下の変化を強くする。両軸が逆向きの場合は階調変化が部分的に相殺されるが、コントラスト低下は両軸の傾きの大きさで決まる。

未乗算sRGBの各成分`x`を`asin(sqrt(x))`へ変換し、方向とColor Shiftに応じた位相差を加え、`sin²`で色へ戻す。位相差0では恒等変換となり、位相が単調な区間を越えると明暗の順序が部分的に反転する。Inversion=0では位相を0〜π/2に制限した応答を使い、1に近づけるほど折り返した応答へ混合する。ガンマに相当する中間調の変化は視線角度から決まり、独立したガンマ設定は持たない。

その後、linear RGBで漏れ光を加え、透過光量を減らす。Contrast Lossはこの段階だけを制御し、階調変換による黒・白の変化は残る。Amountは通常の画像エフェクトと同様に、乗算済みsRGBで入力と混合する。

両角度が0またはAmountが0では、RGBの範囲制限や色空間変換を省いて入力をそのまま返す。加工時の階調モデルは未乗算RGBの0〜1を対象とし、範囲外は制限する。alphaを保持し、unpremultiply → 加工 → premultiplyで半透明色も不透明色と同じ応答にする。完全透明な入力は透明のまま返す。

描画履歴・時刻・乱数を使用しない1パスの処理。解像度・フレームレート・縦横比に依存せず、通常のShaderInputのFit / Wrap / Filterと画像出力形式に従う。登録は`_def_.ts`・`_impl_.ts`の既存globで行う。

## 使用例

- 水平角度を0、垂直角度を45〜70°にすると、階調反転と色の変化が強く出る。負の角度では反転する階調の範囲が変わる。
- 白っぽくなる変化を中心にする場合は、Inversionを0にし、Contrast Lossを上げて角度を調整する。
- 角度へNoiseやグラデーションのスカラー場を接続すると、面の傾きが場所によって異なるような色変化を作れる。
