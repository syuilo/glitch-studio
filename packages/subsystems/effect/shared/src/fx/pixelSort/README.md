# Pixel Sort

入力画像の各行または列を輝度で並べ替える。Horizontalは左から右、Verticalは上から下へ並べ、Orderで昇順・降順を指定する。Cell Sortを含む他のエフェクトの実装には依存しない。

## 範囲と透明度

Threshold Min以上・Threshold Max以下の画素を対象とし、範囲外の画素は固定してソート区間の境界にする。上下限は両端を含み、逆転した場合は交換して扱う。既定値はMinが0、Maxが0.5。Shadowと単独のThresholdは設けない。

UIのスライダーは0〜1を扱うが、式による値を0〜1へ制限しない。HDRや負の輝度も任意の範囲で指定できる。非有限の上下限はそれぞれ既定値へ戻す。

輝度は入力のpremultiplied RGBをalphaで割った色へ係数`(0.2126, 0.7152, 0.0722)`を掛けて計算する。半透明の白を不透明な灰色より暗い色として扱わない。完全透明の画素は範囲によらず固定し、区間の境界にする。NaNの輝度も範囲判定を満たさず固定される。

出力は移動元のpremultiplied RGBAをそのまま使うため、色と透明度が一緒に移動し、alphaを二重に乗算しない。同じ輝度では昇順・降順のどちらでも元の順序を保つ。

## GPU処理

入力接続のFit・Wrap・Filterを適用した、出力画素の中心の色を対象とする。区間の識別と最終描画は同じ入力関数・同じ座標を使う。

行・列ごとに一度走査して区間を識別し、区間番号・輝度・移動元の画素番号を二つのstorage bufferで並列mergeする。RGBA自体はソートせず、最終描画で元の入力を読む。CPUへの読み戻しや描画履歴への依存はない。

buffer上限に応じて行・列をまとめてバッチに分けるが、ソート区間を分断しない。各merge段階のuniformには別領域を割り当て、Threshold Min/Maxも全バッチ・全段階で同じ値を使用する。
