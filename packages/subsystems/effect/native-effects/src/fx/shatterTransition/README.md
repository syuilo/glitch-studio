# Shatter Transition

画像Aを隙間のない不規則な三角形へ分割し、各破片を3D空間で移動・回転させ、画面に固定したBを露出させる。厚みのない両面の板として描画し、裏面には暗くしたAを同じ材料座標で貼る。裏返った画像は自然に鏡像になる。

## パラメータ

| 名前 | 意味 |
| --- | --- |
| `inputA` | 飛散する画像または色。動画は各時刻の入力を破片へ貼る。 |
| `inputB` | 下から現れる画像または色。画面に固定する。 |
| `progress` | 0で完全なA、1で完全なB。0〜1へclampする。 |
| `fragmentSize` | 三角形の元になる格子の代表的な幅。Size Referenceに対する距離比率。 |
| `irregularity` | 内部の共有頂点の不規則さ。0で規則的、1で最大。0〜1へclampする。 |
| `center` | 飛散と開始遅延の中心。長辺全体=1の共通座標で指定する。 |
| `spread` | 外向きの移動量。Size Referenceに対する距離比率。負値は0として扱う。 |
| `depth` | 奥行き方向の移動量。正で奥へ、負で手前へ。Size Referenceに対する距離比率。 |
| `rotation` | ランダムな軸まわりの代表的な回転量。turn単位。負値で回転方向を反転できる。 |
| `gravity` | 下方向への落下量。負値なら上へ浮く。Size Referenceに対する距離比率。 |
| `stagger` | 中心から遠い破片ほど開始を遅らせる強さ。0で一斉開始。0〜1へclampする。 |
| `perspective` | 遠近感。0で平行投影。0〜1へclampする。 |
| `shading` | 固定の正面光＋環境光による陰影。0で無効。0〜1へclampする。 |
| `seed` | 分割形状・軌道・回転の乱数Seed。32bit整数として扱う。 |
| `sizeReference` | 破片サイズと移動距離の換算基準。Centerの座標や空間単位は変えない。 |

A / B / Progressはノード接続に対応する。その他のパラメータは式・キーで制御できる。イージングはProgressへ指定する。分割形状と軌道を安定させるため、通常はトランジション中のFragment Size / Irregularity / Seedを固定して使う。

## 分割形状

出力と同じ縦横比の有限矩形を、代表サイズに収まる行数・列数へ等分する。各セルを交互の対角線で2つの三角形に分ける。内部の共有頂点は各軸でセル幅の最大22%だけずらし、外周は固定する。三角形の反転や分割前の亀裂を避け、0の進捗では元画像を隙間なく覆う。

分割密度は解像度ではなく寸法の比率で決まる。GPUのstorage buffer容量やdispatch上限を超える細かさの場合は、密度を黙って変えず、Fragment Sizeを大きくするようエラーで案内する。

## 進捗と運動

Progressのscalar場は、分割前の各破片の重心で一度だけ読む。その値を破片全体に使うため、空間場を接続しても破片は剛体を保つ。一様な進捗では全破片を同じ時間軸で制御できる。

Centerから破片の重心までの距離をd、Centerから矩形の最遠隅までの距離をDとする。開始遅延と局所進捗は次の式で決める。

```text
delay = 0.8 * stagger * d / D
t = clamp((progress - delay) / (1 - delay), 0, 1)
```

最大の遅延でも全体の80%までとし、全破片がProgress=1で完了するようにする。退いた破片の位置でProgressを読み直すことはない。

画面内ではCenterから外向きに、局所進捗tに比例して移動する。方向は±約14度、移動量は0.7〜1.3倍の安定したランダム差を付ける。重心がCenterと一致する場合はSeedで決まる方向を使う。奥行き方向にも0.7〜1.3倍の移動差を付ける。重力はYへ`-gravity * t²`を加える。

各破片は元の重心を軸に回転する。回転軸は球面上で一様に選び、回転方向は正負ランダム、回転量はRotationの0.5〜1.5倍とする。

これらは秒単位の速度ではなく、トランジション全体に対する変位・回転量。時刻や過去フレームを積算せず、現在の入力・パラメータだけから計算する。スクラブ・逆再生・再生時間の変更でも同じProgressなら同じ状態になる。逆再生はProgressを戻して行う。

## 投影・裏面・陰影

内部では長辺全体=1、中央原点、+Yが上、+Zが手前の3D座標で計算する。変形後の位置を(x,y,z)、Perspectiveをkとすると、画面上の位置は次の通り。

```text
w = 1 - kz
screen = (x, y) / w
```

GPUへは同次座標のまま渡し、透視補正した材料座標で画像を参照する。手前への飛散でカメラ面を跨ぐ場合も、CPUやシェーダーでwによる除算を行わず、GPUのクリッピングを使う。描画領域外はクリップする。

両面を表示し、裏面は元のAのRGBを0.65倍する。陰影の倍率は、回転した法線をnとして`1 - shading * 0.45 * (1 - |n.z|)`。alphaやCoverageは変えない。裏面の0.65倍はShading=0でも適用する。

画像入力は接続のFit / Wrap / Filterを適用して出力解像度の材料画像へ取り込み、面積平均でmipmapを作る。回転・縮小後は線形補間と最大16倍の異方性フィルタで読む。材料画像の更新は毎回行い、飛散開始時の静止画を履歴として保持しない。定数色とCoverage単独では材料画像を確保・更新しない。

## 前後関係・透明度・フェード

4サンプルのMSAAとdepth bufferで、サンプルごとに最前面の破片を選ぶ。共有辺の被覆を二重に加算せず、回転した三角形の輪郭もアンチエイリアスする。画像のalphaは隠面判定へ使わない。

各破片の局所進捗の最後の15%で、`f = 1 - smoothstep(0.85, 1, t)`により被覆を滑らかに落とす。飛散・回転を0にしても終端で突然消えない。フェード中も最前面の破片を選び、退く割合だけBを露出させる。被覆が0の破片は描画しない。

MSAAの各サンプルに、最前面の破片の「premultiplied RGBA × f」と「f」を別々に記録して平均する。平均した色をC、被覆をK、Bの色をBとすると、最終画像は`C + B * (1 - K)`となる。透明な破片の下へBをsource-overで透かさず、幾何的な置換として扱う。

一様なProgressが0以下・1以上のときは元のA/Bを直接読み、余分な分割・材料画像・depth bufferを必要としない。HDR・負のRGB・半透明を保持し、色空間はpremultiplied alphaのlinear sRGB、画像形式はrgba16float。

## 出力と実行

- `output`: 合成画像。主出力。
- `coverage`: 画面上に残っている最前面の破片の被覆率。0がBだけ、1が完全に破片に覆われた状態。画像のalphaや陰影には依存せず、輪郭のMSAAと終盤のフェードを反映する。

Coverageは移動・回転後の被覆を表す。元のA/BをCoverageだけでMixしても同じ画像にはならない。追加の発光や色変化などを連動させる用途を想定する。

配置の生成時に、使用する出力だけを確保する。Coverage単独では色の描画先やA/Bの読み取りを省く。内部のMSAA用Coverageはr16floatとし、公開出力は`enable32bitDataTextures`に応じてr16float / r32floatへ書き出す。

`transition` / `transform` / `composite`タグを持つ。自動解像度はA/Bを参照する。ComputeとRender Passはctxのラッパーを経由し、多数の破片にはレンダラーのタイル描画を利用できる。所有するbuffer・材料画像・中間描画先・入力bindingsはdisposeで解放し、借用した入力・fallback・公開出力は破棄しない。

## 検証

`test/shatter-transition.gpu.test.mjs`で、端点の連続性、隙間のない分割、透明度・HDR、終盤フェード、重心での局所進捗、全入力構成と接続設定、動画相当の入力更新、未使用出力と32bit Coverage、解像度・Size Reference・Seed・再生順序、カメラ面のクリッピングを実際のWebGPUで検証する。

既知の2枚の三角形については、CPU側のquaternion逆回転とレイ/平面交差を使った独立した期待値で、材料座標・透視投影・裏面・重なり順を照合する。

`CHROME_PATH`を設定して実行する。任意で`SHATTER_TRANSITION_PREVIEW_PATH`にPNGの保存先を指定すると、同じGPU出力から外向きの飛散・手前への飛散・落下・Coverageを比較する画像を保存する。
