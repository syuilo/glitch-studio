# Soft Clamp

画像の明度を指定した下限・上限へ収め、各境界をなだらかに繋ぐ。Tone Compressionが範囲外にも傾きを残すのに対し、Soft Clampでは移行区間の外を一定の明度へ揃えるため、その領域の明度差は失われる。

## パラメータ

Input／Outputはcolor。全ての数値パラメータは式・キー・ノード入力に対応する。

| パラメータ | 作用 |
| --- | --- |
| Lower Limit (Oklab L) | 出力明度の下限 |
| Lower Softness | 下限を中心とする移行区間の幅。単位はOklab L |
| Upper Limit (Oklab L) | 出力明度の上限 |
| Upper Softness | 上限を中心とする移行区間の幅。単位はOklab L |

OklabのLは黒が0、基準白が1、linear RGBの18%グレーが約0.565。RGB各成分の値やlinearの輝度とは異なる。上下限のUI範囲は0〜1だが、式やノード入力では負値・1超も受け付ける。上下限が逆転した画素では小さい値を下限、大きい値を上限とする。Softnessは入れ替えず、Lower Softnessは数値的な下限、Upper Softnessは数値的な上限に作用する。上下限が一致する場合は、その明度へ揃える。

Softness=0では通常のclampとなる。正の値では閾値の前後へ半分ずつ移行区間を広げ、境界での傾きも連続にする。負値は0として扱い、1超も受け付ける。例えば下限0.2・Lower Softness=0.2なら、入力L<=0.1は0.2、L>=0.3では下限側の補正なし、その間を二次曲線で繋ぐ。入力L=0.2は出力L=0.225となる。空間的なぼかしではない。

移行区間が重なる設定では、両Softnessの比率を保ち、合計が上下限の差の2倍になるまで幅を縮める。片側だけを広くした設定にも同じ規則を使う。例えば上下限0.25〜0.75、Softnessが両方1の場合、実効幅は両方0.5となり、L=0.5で二つの曲線が繋がる。明暗の反転や指定範囲からのはみ出しを起こさない。

## 処理と色の規約

未乗算のlinear sRGBをOklabへ変換し、a/bを保持してLだけを補正する。下限を`a`、上限を`b`、実効的な半幅を`hL`／`hU`とすると、`hL + hU <= b - a`になるように調整し、以下を適用する。

- `L <= a - hL`: `a`
- `L >= b + hU`: `b`
- 下限の移行区間: `a + hL / 4 * ((L - a) / hL + 1)^2`
- 上限の移行区間: `b - hU / 4 * ((b - L) / hU + 1)^2`
- 中間の対象外領域: 元の`L`

半幅0の側では移行区間の計算を行わない。曲線の傾きは0〜1で、同じパラメータなら明暗の順序を保つ。画素ごとにパラメータを変える場合、異なるパラメータの画素間の順序までは保証しない。

出力はlinear sRGBへ戻し、元のalphaを再乗算する。入出力はpremultiplied alphaのlinear sRGB・rgba16floatで、alphaは変更しない。alpha=0の透明色・発光は未乗算の色を定義できないため、上下限の適用対象とせず、そのまま通す。対象外の中間調も入力を直接返し、色空間変換の往復誤差を避ける。

制限するのはOklabのLだけであり、RGB各成分ではない。a/bを保持するためOklabの色相・クロマは維持するが、RGBの成分比・彩度や表示色域への収まりは保証しない。上下限を0〜1にしてもRGBには負値・1超が残り得る。色域やSDR出力の範囲を保証する処理ではない。設定した明度範囲は色空間変換・float16保存の丸め誤差を伴う。

HDR・負値も入力でき、設定した明度範囲へ制限する。上下限自体は0〜1へclampしないため、例えば上限L=2では無彩色のlinear RGB=8まで出力できる。

1描画パスで完結し、時刻・乱数・履歴・解像度・アスペクト比に依存しない。自動解像度はInputから決める。
