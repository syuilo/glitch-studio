# Effect Renderer

エフェクトの実行インスタンスとGPU出力を管理する。ノード・Visual Module・レイヤーなどの配置や式のスコープは呼び出し側が所有する。

`prepare()`は準備の開始・更新だけを行う。同期の描画ループは`checkReady()`で描画可能か確認し、準備中のフレームをスキップできる。準備失敗では元の診断をthrowする。準備完了を待つ呼び出し側は`waitUntilReady(signal)`を使う。

`custom-shader-effect.ts`は、Custom Shader Effectの入出力定義とユーザーWGSLから単一パスの実装を生成する。共通座標と内部の画像参照座標を境界で換算し、各入力は既存のShaderInputのFit／Wrap／Filterで読む。全出力を同じ解像度で確保・描画し、画像出力は`rgba16float`、データ出力はデータ精度の設定に従う。コンパイルは使用箇所ごとに行い、loading／error／readyをEffectRendererへ通知する。ユーザー本文を先頭へ置いて診断の行・列を保ち、失敗時に旧pipelineへフォールバックしない。登録一覧・Project・Node・Layer・時計は所有しない。

`resetRenderHistory()`は実行インスタンスと確保済みの出力・前フレームテクスチャを作り直す。呼び出し側が`dependsOnRenderHistory`を調べて対象を選び、リセットのタイミングを決める。実装内に独自に保持する履歴も初期化し、未確保の遅延出力・解像度・借用リソースは維持する。準備中の待機と古い状態通知を無効化し、`resourceVersion`で出力の変更を伝える。次の描画だけ経過時間・ポインター移動量を0にし、絶対時刻は呼び出し側が渡した値を使う。

ポインターの位置・移動量は、エフェクト実装と同じ長辺全体=1の共通等方単位で受け取り、そのまま渡す。プレビューの画像参照座標からの換算は呼び出し側が所有する。Visual Moduleではノードごとの描画領域で一度換算し、式の`POINTER_POSITION`とエフェクトの描画で同じ値を使う。

`effect-parameter-value.ts`は評価済みの通常パラメータを`ShaderInput`へ変換する。素材・Playerの参照は通常パラメータに含めない。`effect-static-settings.ts`が保存済みの静的設定IDから借用リソースを解決し、`EffectRenderer`は`init.resources`へ渡す。Playerは現在の正規化済みテクスチャと表示寸法を返す`getVideoTexture()`として渡すため、選択は固定でも内容は更新される。VideoFrameの所有・linear化・ノード間の画像共有は呼び出し側が担当し、エフェクトは借用画像を変換・破棄しない。デコーダー・非同期準備・キャンセル・世代管理は維持する。

画像は`GPUTexture | null`、動画・フォント・LUTは`FileSource | null`として渡す。画像のGPU転送は呼び出し側がリソース解決前に完了させる。画像のnullは未選択だけを表し、選択済みの画像にテクスチャがなければ読み込み失敗として通知する。素材IDや寸法のメタデータは解像度計画・リソース解決側で扱い、エフェクト実装にはファイルの読み取り口だけを渡す。

解像度は出力確保と初回の式評価より前に呼び出し側が決定し、コンストラクターへ必ず渡す。寿命中は固定し、変更時は`EffectRenderer`自体を破棄・再作成する。出力の途中交換や解像度未確定の状態は持たない。自動解像度の優先順位は、`intrinsicResolutionSetting`で指定した素材メタデータ、`resolutionInputParameters`で宣言した接続の計画寸法、描画先の順。配列・構造体は配下の全接続を調べ、最大画素数の幅・高さを使う。同数では定義・保存順で先頭を優先する。定数には固有寸法がない。GPUテクスチャ・現在のPlayerフレーム・式の評価結果から寸法を決めない。

原寸には全体の描画倍率、入力には上流で適用済みの倍率を使い、`auto`・`context`ではさらに自身の倍率を掛ける。各段階で四捨五入・最低1pxとし、GPU上限を検証する。`customAbsolute`は全体倍率だけを適用する。

静的設定と借用リソースはコンストラクターで受け取り、寿命中は変更しない。静的設定の変更時は呼び出し側が`EffectRenderer`自体を破棄・再作成し、新しいリソース世代を後段のキャッシュへ伝える。借用した素材は破棄しない。Visual Moduleでは通常パラメータの値だけの編集を除き、全エフェクトを再作成する。

フォント・LUT・Video Frameのローダーは生成時に素材を固定する。フォントとLUTは一度だけ読み込み、Video Frameは同じ素材への時刻要求だけを更新する。素材変更に対するローダー内の切り替え・再解決は行わず、インスタンス破棄後の非同期結果を無視する。

## タイル描画

`effectRenderTiling`は`{ mode: 'auto' }`（既定）、`{ mode: 'disabled' }`、`{ mode: 'manual', tileSize }`。手動の`tileSize`は各タイルの幅・高さの最大値をpxで指定する。自動では定義の`canHaveLongRunningRenderPass === true`だけを対象とし、それ以外は従来の`render()`で呼び出し側のencoderへ記録する。呼び出し側は`shouldRenderTiled(context)`で当該描画の実行経路を選ぶ。各エフェクト実装の`render()`は同期のまま一度だけ呼び、記録したパスを全体サイズのviewport・テクスチャへScissorで再生する。各パスの全タイルが終わってから次へ進み、clearは元のパスにつき一度だけ行う。内部のmipや縮小テクスチャも実際のView寸法で分割する。

Compute Passは分割しない。コピー・バッファ初期化を含む元のコマンド順序を維持し、各タイルのsubmit後にGPU完了を待つ。GPU時間は各実パスのtimestampの合計で、CPU待機は含めない。タイル化ではVertex Shaderの仕事は減らず、1画素の計算が長すぎる場合にもタイムアウト防止は保証できない。Occlusion Queryを持つパスはクエリ結果を上書きしないよう分割しない。

`renderTiled()`の完了まで同じインスタンスの次の描画や準備を開始しない。出力と前フレームの交換は全コマンドの完了後に行う。中断は送信済みのGPU処理が終わった境界で検出し、未送信タイルを破棄して内部状態を初期化する。破棄要求も実行中のリソース解放を完了境界まで遅延する。

`renderTiled(context, signal, onProgress)`の任意の進捗通知は、一つのエフェクト内の全Render Passについて`{ completedTiles, totalTiles }`を返す。送信前は完了数0と全パスの予定総数を通知し、完了数はGPU完了後にだけ進める。自動分割の変更時は未送信部分の予定数から総数を更新し、完了数は戻さない。未送信タイル数は二分時の端数と寸法下限を含めて計数し、上限が変わらない間は再計数しない。Compute Pass・コピーはタイル数に含めない。完了・中断・失敗時はnullを通知する。通知を省略した呼び出しでは進捗のための計数を行わない。

自動制御はRender Passごとに64×64画素以下から開始し、submit直前からGPU完了通知までの実経過時間を測る。制御目標は32ms。通知遅延をGPU負荷と誤認して細分化し続けないよう、32ms超が3回連続した場合に未送信領域を縮小する。128ms以上は1回でも縮小する。面積を減らしても待機時間が変わらない場合に学習した縮小下限は、間に速いタイルが入っても保持し、大幅な時間増加や計算量・条件変更時には64pxの固定下限まで戻す。ヒントや遅延で縮小した後、24ms未満の完了が4回続けば、同じパス内でも初期の4096画素以下まで面積を回復する。その上限を超える拡大は、全領域が十分軽く完了した場合だけ次回に最大2倍まで行う。最初の軽い領域だけを根拠に、未観測の領域を初期上限より大きく描かない。自動制御自体はTimestamp Queryを要求しない。統計が有効な場合のGPU時間は引き続きtimestampで計測し、実経過時間と混同しない。

自動分割の固定下限は各辺64pxで、通常の描画先では64×64画素より小さくしない。計算量ヒントの急増による事前縮小にも適用する。描画先自体の辺が64px未満なら、その実寸を下限とする。奇数寸法の二分で子の辺が64px未満になる場合は、面積の目標上限より寸法の下限を優先して分割を止める。手動のタイル寸法にはこの下限を適用しない。

`EffectImplementation.getRenderWorkloadHint({ params, usedOutputPorts })`は任意で、`{ key, workPerPixel }`またはnullを返す。評価済みパラメータから、同じkey内だけで比較できる正の計算量を画素あたりで表す。反復数・AAサンプル数などを増やした場合は、その比率で前回の面積上限を実行前に縮小する。処理方式・入力内容など、計算量だけでは比較できない変更はkeyへ含める。入力内容を追跡できない場合はnullを返す。ヒントなしでは描画ごとに小さいタイルへ戻り、同じ条件だと確認できる場合だけ学習を再利用する。解像度・pipeline・key変更、履歴リセット、中断・失敗でも学習を破棄する。

画面全体を十分軽く描けた条件では通常描画へ戻し、30回の実描画ごとに再計測する。間引き中もヒントの変更は毎回確認する。対象の指定漏れ、入力条件を識別しないヒント、1画素だけでも長時間を要する処理などに対して、HUNGの防止を保証するものではない。計算量ヒントは描画結果や反復数・精度を変更しない。
